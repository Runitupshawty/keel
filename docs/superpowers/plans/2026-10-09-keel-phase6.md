# Keel Phase 6 Implementation Plan: library core (Spacedrive-class)

> **For agentic workers:** same rules as the Phase 2-5 plan headers. Read spec 2.10 (library layer) first, then 2.5, 2.9, the Phase 1 Global Constraints + Amendments, and the keel-search / keel-vfs APIs you build on. The library is additive: every existing screen keeps working with the library disabled (setting `library.enabled`, default on after first run).

**Goal:** Keel knows every file James owns across his sources, even when the drive or host is offline: a per-source SQLite store with full-text search, stable identity across moves, BLAKE3 content ids with a duplicate finder, tags/favorites/recents/saved views, an Overview dashboard, durable jobs with restart recovery, and `validate → preview → execute` for every mutating operation.

**Crate:** `crates/keel-core` (new). Depends on keel-vfs (providers, VPath, ops) and keel-search (Hit type). keel-app depends on keel-core. No daemon yet (in-process); the API surface is shaped so `keel-daemon` can wrap it later (every operation is a typed request/response, no egui types).

**Global constraints:** indexing never blocks the UI (dedicated job threads, bounded channels); SQLite via `rusqlite` bundled, WAL, one connection pool per store; every write goes through a job with an operation log entry; hashing is opportunistic (idle time, bounded CPU: one thread, lowest priority, pauses when the app is busy or on battery); the library files live under `<data dir>/library/<library>/` and each source's `source.db` under `<data dir>/library/<library>/sources/<source id>/` so it can be moved with its data.

**Review focus:** (1) a source directory with 2 million files indexes without exhausting memory (streaming inserts, batch 5,000); (2) a rename of a 100k-file directory keeps record identity (no re-hash); (3) a source going offline mid-index leaves a consistent generation; (4) FTS queries stay < 50 ms on 2M rows; (5) duplicate detection never reports false positives (full hash confirms); (6) the operation log never records a secret or a path outside the library.

### Task 27: `keel-core` library + source stores + indexer (worktree `task27`)

**Interfaces (Produces):**
```rust
pub struct Library { pub id: LibraryId, pub name: String, root: PathBuf, db: Pool, sources: RwLock<Vec<Arc<Source>>>, jobs: Jobs }
impl Library { pub fn open(root: &Path, name: &str) -> Result<Library>; pub fn list() -> Vec<LibrarySummary>; pub fn add_source(&self, def: SourceDef) -> Result<SourceId>; pub fn remove_source(&self, id: SourceId, delete_store: bool) -> Result<()>; pub fn sources(&self) -> Vec<SourceSummary>; pub fn stats(&self) -> LibraryStats; }
#[derive(Clone, Debug, Serialize, Deserialize)] pub struct SourceDef { pub label: String, pub root: VPath /* file://, sftp://, cloud://, archive-free */, pub kind: SourceKind /* Folder, Drive, Share, Cloud, Device */, pub include_hidden: bool, pub ignore: Vec<String> /* gitignore-style */ }
pub struct Source { pub id: SourceId, pub def: SourceDef, store: Pool /* source.db */, pub generation: AtomicU64, pub status: RwLock<SourceStatus> /* Online{indexed_at}, Indexing{done,total}, Offline{last_seen}, Error(String) */ }
// source.db schema (migrations in keel-core/src/schema.sql, versioned):
//   record(id INTEGER PK, parent INTEGER, name TEXT, kind INT, size INT, mtime INT, ctime INT, fs_id TEXT /* file-id/inode or path hash for remotes */, cas_id BLOB NULL, sampled_hash BLOB NULL, gen INT, flags INT /* unreadable, hidden, link */, error TEXT NULL)
//   record_fts(name, path) USING fts5 (content=record, tokenize='unicode61 remove_diacritics 2')
//   tag(id, name, color, parent), record_tag(record, tag)
//   op_log(id, ts, kind, payload JSON, result)
//   meta(key, value): schema_version, generation, journal cursor (for USN/watch), last_full_walk
pub struct Indexer; impl Indexer { pub fn full_walk(src: &Source, router: &Router, progress: &dyn Fn(IndexProgress), cancel: &AtomicBool) -> Result<()>; pub fn watch(src: &Source, router: &Router) -> Result<WatchHandle> /* notify for local; polling every N minutes for remote/cloud */; pub fn apply_change(src: &Source, ev: ChangeEvent) -> Result<()>; }
// Identity: local = volume serial + file id (Windows FILE_ID_INFO / unix dev+inode) so a rename updates name/parent only; fallback = parent+name.
pub struct Jobs { /* durable: job(id, kind, state JSON, status, progress, log) in library.db; resumed on open */ }
pub trait Job: Send { fn kind(&self) -> &'static str; fn run(&mut self, ctx: &JobCtx) -> Result<()>; fn checkpoint(&self) -> serde_json::Value; fn restore(v: serde_json::Value) -> Result<Box<dyn Job>> where Self: Sized; }
pub fn validate_preview_execute<O: Operation>(lib: &Library, op: O) -> Result<Plan<O>>; // Plan { changes: Vec<Change>, warnings: Vec<Warning /* LastCopy, OfflineSource, .. */> }; plan.execute(lib) runs as a Job and logs to op_log
```

**Steps:** (1) crate + schema + migrations + Pool (r2d2-less: a small mutex-guarded connection set) with tests; (2) `Library::open/list/add_source/remove_source` + `LibraryStats`; (3) `Indexer::full_walk` streaming inserts in 5,000-row transactions with progress, cancel and generation bump; unreadable entries kept with error; 2M-entry synthetic perf test `#[ignore]` (< 90 s, < 400 MB RSS); (4) identity: file-id based move/rename tracking test (rename a 10k dir, zero re-inserts); (5) `watch` for local sources (notify) + polling for remote/cloud with generation snapshots; (6) durable Jobs: persist/restore/cancel tests (kill mid-job, reopen, resumes); (7) `validate_preview_execute` for Copy/Move/Delete/Rename operations with a `LastCopy` warning when the content id has no other record; (8) op_log with redaction tests; commit `feat(core): library, source stores, streaming indexer, durable jobs, validate/preview/execute`.

### Task 28: content identity + duplicate finder + library search (worktree `task28`, after 27)

- Hashing job: sampled hash (first/middle/last 64 KiB + size) for all records, full BLAKE3 only for sampled-hash collisions; runs at idle, one low-priority thread, pauses while the UI reports activity or on battery (`battery` crate or platform query); checkpoint every 1,000 files.
- `cas_id` links; `Library::duplicates(min_size) -> Vec<DupGroup>`; "last copy" computation; `redundancy(record) -> Copies { count, volumes }`.
- Search: `Library::search(q: LibraryQuery) -> Vec<LibraryHit>` across all sources: FTS5 on name+path with prefix/phrase, filters kind/size/date/source/tag/extension, offline-aware (status shown per hit), ranked (bm25 + recency); 2M-row query < 50 ms test; `Searcher` adapter so the app's search tab can target "Library" as a backend.
- Tags: create/rename/color/nest; apply/remove on records; favorites + recents (recents from op_log and open events); saved views (`View { name, query, layout }`).
- Commit `feat(core): content ids, duplicate finder, library search, tags/favorites/recents/views`.

### Task 29: app integration (worktree `task29`, after 28)

- Sidebar: Overview (dashboard: total/used storage per device/drive, files indexed, unique content ids, sources + status, running jobs), Favorites, Recents, Sources (devices/locations with status dots + indexing progress), Tags, Views. "Add source…" wizard (folder/drive/share/cloud/remote; include hidden; ignore patterns).
- Library tab kind: a virtual folder listing from the store (works offline), with the same views/preview; `library://` VPath scheme provider in keel-vfs that resolves to the real path when online and shows "offline (last seen …)" otherwise; search tab backend selector (Everything/Spotlight/… vs Library).
- Tag UI: tag chips in details view, Ctrl+T to tag selection, tag colors; favorites star; recents list.
- Jobs panel shows library jobs with resume after restart; validate/preview dialog for copy/move/delete from library views ("3 files, 1 is the last copy of its content").
- Duplicate finder window (groups, sizes, keep-one actions through validate/preview/execute).
- Settings → Library: enable/disable, libraries list (create/switch), hashing idle policy, CPU/battery pause.
- Tests: sidebar model from library stats; library tab listing from a fixture store; tag apply/remove round-trip; preview dialog warnings; search backend switch.
- Commit `feat(app): library sidebar, overview, sources, tags, duplicate finder, validate/preview dialogs`.
