# Keel Phase 10 Implementation Plan: parity gaps (shell menu, undo, previews, folder sizes, themes)

> **For agentic workers:** same rules as earlier plan headers. Read [docs/parity.md](../../parity.md) first: it is why these five tasks were chosen, and it ranks what comes after them. Each task gets its own worktree, branched from the release Phase 10 starts on. Run `cargo fmt --all --check`, `cargo clippy --all-targets -- -D warnings` and `cargo test --workspace` before every commit. Any new parser of outside bytes gets a fuzz target (see [docs/fuzzing.md](../../fuzzing.md)). Every user-visible change goes into the docs and the CHANGELOG in the same task. Public repo: no hostnames, IPs, user names, personal names or personal paths in code, tests, fixtures, screenshots or commit messages.

**Goal:** Close the five gaps that most often send a user back to Explorer or that spec section 1 asks for and Keel lacks: the Windows shell context menu, undo for file operations, previews of the formats the spec listed but never got (HEIC, AVIF, camera RAW, audio, fonts), folder sizes, and color themes beyond dark and light.

**Not in this phase** (ranked in [docs/parity.md](../../parity.md#ranked-gaps)): FTP and FTPS (#6), the parallel small-file copy queue (#7), WSL integration (#8), and a fuzzy finder over files (#12) are the next small wins, the obvious Phase 11. Folder sync (#13) and content search (#11) are each a phase of their own.

**Live checks.** Wherever a brief says "live", run it on the owner's own Windows desktop, and on a Mac or Linux machine of the owner's where noted. Use only generated fixtures in a temporary folder (`%TEMP%\keel-p10-<task>` or `$TMPDIR/keel-p10-<task>`), with `KEEL_CONFIG_DIR` and `KEEL_DATA_DIR` pointed at a throwaway folder so the owner's settings and library are never touched. A check against a real personal file (an iPhone photo, say) may be done by eye, but it is never committed, screenshotted or named in a commit. Screenshots for the docs come from `scripts/screenshots.sh` on fixture data.

**Review focus:**
1. Nothing in the shell menu bypasses Keel's preview and trash rules.
2. Undo never overwrites a file and never loses data. When it cannot undo exactly, it says why and does nothing.
3. Every new decoder stays within the existing size and pixel caps, and fails as "damaged file", never as a crash report.
4. Folder totals are correct after watcher bursts, renames across folders and source removal.
5. Theme files from outside cannot run code or read files.

### Task 43: the Windows shell context menu (worktree `task43`)

**Goal:** Right-clicking local files in Keel can show everything Explorer's menu shows: installed handlers (archivers, editors, version control), Send to, Open with, and Share. The entries are also searchable in the command palette. This is the Atlas "searchable context menus" claim and the README roadmap item, and the main missing piece for a week without Explorer.

**Read:**
- `crates/keel-app/src/pane.rs` (`context_menu`) and `palette.rs`.
- `crates/keel-vfs/src/shell.rs`, the Explorer Properties sheet: the pattern for Windows shell calls kept out of `keel-app`.
- `crates/keel-vfs/src/drag_out/win.rs`, for OLE/COM initialization on the UI thread.
- `docs/files.md`, and the README roadmap.

**Design points:**
- Add a **More options** entry at the end of Keel's context menu, and also open the shell menu on Shift+right-click and Shift+F10. It builds the shell menu for the selection:
  - `SHParseDisplayName` for each path.
  - The parent's `IShellFolder::GetUIObjectOf(IID_IContextMenu)`.
  - `QueryContextMenu` into a popup `HMENU`, with `CMF_EXTENDEDVERBS` when Shift is held.
  - `TrackPopupMenuEx` on Keel's window, then `InvokeCommand` with the chosen id.
  - Forward `WM_INITMENUPOPUP`, `WM_DRAWITEM`, `WM_MEASUREITEM` and `WM_MENUCHAR` to `IContextMenu2`/`IContextMenu3` through a window subclass (`SetWindowSubclass`) while the menu is open, or Send to and Open with stay empty.
  - All of this lives in `keel-vfs::shell` (a new `context_menu` module); `keel-app` gets a plain Rust interface.
- **Native popup first.** It is what users know, and handlers that draw their own items only work there. For the palette, walk the same `HMENU` (`GetMenuItemInfoW` with `MIIM_STRING | MIIM_ID | MIIM_SUBMENU | MIIM_STATE`) into a list of "Shell: <path of labels>" entries. Skip separators, disabled items and items with no text. The list is built only when the palette opens with a local selection, never on every frame. Invoking an entry runs `InvokeCommand` with the same id offset.
- **Keep Keel's rules.** Read each item's canonical verb (`GetCommandString(GCS_VERBW)`). Remove `delete`, `rename`, `cut`, `copy`, `paste`, `pastelink`, `link` and `properties`: Keel's own entries (with preview, trash, conflict prompts and the in-app Properties) already stand for them. Document this.
- **Scope:** local paths only (the `file` scheme, including UNC shares). For SFTP, cloud, `node://`, archive, `library://` offline, and a selection from several folders (search results), the entry is greyed with the reason, for example "The Windows menu works on files in one folder on this computer". No materialising to a temporary copy: a handler would act on the copy.
- **Risk:** shell extensions run inside Keel's process. A crashing handler kills the window, and Keel's panic safety cannot catch it. The menu is built only on request (never prefetched), and the docs say so. A handler that hangs blocks the window as it would block Explorer; note it in Known limitations.
- **macOS and Linux:** the entry is not shown. A macOS Services menu is a possible follow-up, not this task.

**Tests:**
- Unit tests of the verb filter and of the walk from menu to palette entries. Build a real `HMENU` with `CreatePopupMenu` and `AppendMenuW` in the test (Windows only), including a submenu, a separator and a disabled item.
- An `#[ignore]`d Windows test that builds the shell menu for a temporary `.txt` file and checks it holds the `openas` verb, and that the filter removed `delete` and `rename`. Check verbs, not localized labels.
- A walkthrough flow (kittest) checking that **More options** is greyed with its reason on a remote or archive entry.
- **Live (Windows desktop):** a temporary folder with a generated `.txt`, `.zip` and `.png`.
  - Right-click, then **More options**: the system menu shows, including any installed handlers.
  - Open **Send to** and **Open with** (both submenus fill).
  - Pick **Open with**, choose an app, and close it.
  - In the palette, type `Shell:` and invoke an entry.
  - Check that Delete and Rename are absent.

**Docs:**
- `docs/files.md`: a new section, "Windows shell menu".
- `docs/getting-started.md`: one line under Everyday tasks.
- `docs/features.md`: a bullet.
- README: remove the roadmap line "the native Windows shell context menu".
- CHANGELOG: Added, plus Known limitations (local files in one folder only; handlers run in-process; filtered verbs).

**Commits:**
- `feat(vfs): the Windows shell context menu for local files`
- `feat(app): More options opens the Windows menu; its entries in the palette`
- `docs: the Windows shell menu`

### Task 44: undo for file operations (worktree `task44`)

**Goal:** Ctrl+Z (Cmd+Z) undoes the last file operations: rename, bulk rename, move, copy, new folder or file, and delete to the trash. Keel's first known gap (0.1.0: "no undo") and Spacedrive's `files.undo`.

**Read:**
- `crates/keel-app/src/bulk_rename.rs` (`undo_steps`, `run_steps`: reuse them, do not duplicate) and `jobs.rs`.
- `crates/keel-core/src/plan.rs` and `oplog.rs`.
- `crates/keel-vfs/src/trashbin.rs` (restore) and `ops.rs`.
- `docs/library.md` ("Preview before you act", "Resuming"), and the delete and rename parts of `docs/getting-started.md`.

**Design points:**
- **An undo journal per window**, in memory, with the last 20 completed operations. It is cleared on profile switch.
  - Each entry is recorded only when its job finishes, with exactly what the job did (the paths it created or moved, not the ones it skipped). A job that partly failed records the part that was done.
  - Persisting across restarts is out of scope. Add it when asked; the journal type should serialize, so that is easy later.
- **Reverse of each kind:**
  - **Rename and bulk rename:** the existing `undo_steps`.
  - **Move:** move back, through the same plan path.
  - **Copy:** the copies it created go to the trash.
  - **New folder or file:** to the trash.
  - **Delete to trash:** restore from the Recycle Bin or Trash. On macOS, record the trashed URL that NSFileManager returns, because Original location is unreadable there.
- **Not undoable, and said so in the toast** ("Can't undo: deleted permanently"):
  - permanent deletes (SFTP, S3, WebDAV without a trash, Delete permanently);
  - files replaced by Overwrite;
  - zip edits;
  - operations on `node://` sources;
  - library-only actions (tags and favorites keep their own toggles).
  These kinds are not recorded at all, so Ctrl+Z goes to the entry before them only after the toast has said the newest one cannot be undone.
- **Safety:**
  - An undo that moves or deletes runs as a plan with the usual preview, for example "Undo move: 3 items back to <folder>".
  - It stops before touching anything when an item has changed since (size or mtime), is gone, or when its old place is now taken. It never overwrites, and it never chooses Rename new on its own.
  - A rename undo with a clash stops in the same way.
- **Keys:** Ctrl+Z in a text field stays text undo, and Ctrl+Z in the file list is file undo. Also: **Undo <what>** in the palette, and an **Undo** button on the toast after each operation (bulk rename already has one; generalize it). Redo is out of scope; add it when asked.
- **Attached to the daemon:** the reverse is built from the same API operations (`plan` move, rename or delete, then `execute`). If restoring from the trash has no operation yet, add `files.trash_restore` to `keel-api` with a preview, and document it in `docs/api.md`.

**Tests:**
- Unit tests of the reverse builder for each kind, including partial jobs.
- Integration tests in a temporary folder:
  - a move, then undo: the tree is byte-identical to before;
  - a copy, then undo: the copies are in the trash and the originals untouched;
  - undo refused when the old place is taken, and when the moved file changed;
  - a delete, then undo, through the real Recycle Bin, as in the existing trash tests (`#[ignore]` where the runner has no trash).
- A walkthrough flow: F2 rename, Ctrl+Z, and the name is back. Plus the toast's Undo button.
- **Live (Windows desktop; also a Mac for the delete undo):** in a temporary folder, rename, move between panes, copy, make a new folder and delete, then Ctrl+Z five times. Each step comes back, and the Recycle Bin no longer holds the fixture.

**Docs:**
- `docs/getting-started.md`: an Undo paragraph under Copy, move and delete.
- `docs/files.md`: the keyboard table.
- `docs/features.md`.
- CHANGELOG: Added, plus Known limitations (the kinds listed above; the journal does not survive a restart).

**Commits:**
- `feat(app): undo the last file operations (Ctrl+Z)`
- `feat(app): undo a delete from the Recycle Bin or Trash`
- `docs: undo`

### Task 45: previews of HEIC, AVIF, camera RAW, audio and fonts (worktree `task45`)

**Goal:** The formats spec 2.3 promised and Keel never built. iPhone photos (HEIC) preview and show in the media view; RAW photos show their embedded JPEG; audio files show their tags and cover and play; fonts show a sample.

**Read:**
- Spec 2.3 (the formats table).
- `crates/keel-preview/src/lib.rs`, `image.rs` (the pixel cap and header-declared size checks from 0.17.0) and `video.rs` (`find_tool`, the ffmpeg fallbacks).
- `crates/keel-core/src/sidecars.rs` and `media.rs` (thumbnails, `meta.json`, EXIF through kamadak-exif).
- `crates/keel-app/src/video_player.rs` (the ffmpeg plus cpal sound path).
- `docs/library.md#media-view`, `THIRD_PARTY.md`, `deny.toml`.

**Design points:**
- **HEIC, HEIF and AVIF:** decode through `ffmpeg` when it is on `PATH`. Ask it for one frame as PNG on stdout, at most the preview size, with its display rotation applied. Keel already relies on ffmpeg for video, so nothing new to install or license.
  - Check which ffmpeg version reads HEIF still images, including tiled iPhone images, and say so in the message when the installed one cannot ("HEIC previews need ffmpeg <version> or newer").
  - No libheif (an LGPL C build) and no dav1d. The Windows WIC codec is a follow-up only if ffmpeg proves missing too often: the HEVC extension costs money (see Needs the owner).
  - EXIF capture time and GPS for HEIC through kamadak-exif if it reads HEIF; check, and if not, read them from ffprobe's tags.
  - The media sidecar job uses the same decoder, so `taken:` and date headers work for iPhone photos.
- **Camera RAW** (DNG, CR2, NEF, ARW, ORF, RW2, PEF): show the largest embedded JPEG preview, found by walking the TIFF IFDs (`JPEGInterchangeFormat` and its length, and SubIFDs). Pure Rust; no LGPL raw decoder. Formats that are not TIFF-based (CR3, RAF) say "no embedded preview" unless ffmpeg can read them. Cap the IFD walk (count and depth) and give it a fuzz target.
- **Audio** (mp3, flac, wav, ogg, opus, m4a, aac):
  - The panel shows title, artist, album, duration, codec and bitrate from `ffprobe` JSON (reuse `keel_core::ffprobe_json`).
  - Show the embedded cover art (the attached-picture stream, through ffmpeg) when there is one.
  - Play and Pause with a progress bar, reusing the video player's sound path without a picture.
  - Without ffmpeg, the panel shows the file's name and size, as it does for video.
- **Fonts** (ttf, otf, ttc):
  - Render "The quick brown fox jumps over the lazy dog 0123456789" at a few sizes into an RGBA image with `ab_glyph`, which egui already depends on, so this adds no new crate. Show it through the existing image preview.
  - Show the family and style from the font's name table.
  - woff and woff2 are left out for now (woff2 needs a brotli decoder); they show as unknown, as today.
  - A fuzz target for the font path.
- **Limits:** the same pixel cap and header-declared size checks as images; an ffmpeg that runs past the preview timeout is abandoned, as for video.

**Tests:**
- Fixtures generated by the tests, never personal media:
  - a 1-second sine tone as FLAC and MP3 with tags and a cover, made with ffmpeg in the test;
  - a tiny DNG built in the test with an embedded JPEG;
  - a HEIC and an AVIF of a synthetic pattern, committed once, each under 20 KB, with how they were made written next to them.
- ffmpeg-dependent tests are `#[ignore]` unless ffmpeg is found, as the video tests are.
- Font sample from egui's bundled default font (its license is already in `THIRD_PARTY.md`).
- Fuzz targets: the RAW IFD walker, and the font sample.
- **Live:**
  - Windows desktop and a Mac: the fixtures in a temporary folder, in the preview panel and in the media view (the HEIC tile shows; `taken:` finds it). Play the FLAC.
  - Then, by eye only, one real iPhone HEIC and one RAW of the owner's own. Not committed, no screenshot.

**Docs:**
- `docs/features.md`: the previews list.
- `docs/getting-started.md`: the ffmpeg line, which now also covers HEIC and audio.
- `docs/library.md`: the media view supports HEIC and RAW.
- CHANGELOG: Added, plus Known limitations (the ffmpeg version for HEIC; CR3 and RAF; no woff).

**Commits:**
- `feat(preview): HEIC and AVIF photos through ffmpeg`
- `feat(preview): camera RAW files by their embedded preview`
- `feat(preview): audio files with tags, cover art and playback`
- `feat(preview): font samples`
- `feat(media): HEIC, AVIF and RAW in the media view`

### Task 46: folder sizes and a Sizes view (worktree `task46`)

**Goal:** Folders show their total size, and a Sizes view shows what fills a folder or a disk, like Spacedrive's Size view and WizTree's tree list. Today a folder counts as 0 B (QA 2026-10-10).

**Read:**
- `crates/keel-core/src/schema.sql` (`record.parent`, `record.size`, `record_parent` index), `index.rs` (walks and watcher batches) and `library.rs` (stats).
- `crates/keel-app/src/view_details.rs`, `pane.rs` and `worker.rs`.
- `docs/library.md` and `docs/performance.md`.

**Design points:**
- **Inside a library source:** keep folder totals with the index, in a `folder_total(record, bytes, files)` table.
  - Filled bottom-up once at the end of each walk (one pass over records ordered by depth).
  - Kept current from watcher batches by adding each change's delta along its parent chain: an add or remove is one chain, and a move across folders is two.
  - Removed with its source.
  - Measure it at 200,000 and 2,000,000 records and add the rows to `docs/performance.md` and `scripts/perf.sh`. Budget: under 10 % added to a first walk.
- **Outside the library** (or with it off), **Calculate sizes** is a pane action (palette, and the view menu). It runs a cancellable background walk of the shown folder's subfolders, in the jobs panel, and caches totals per session by path and mtime.
  - It never starts on its own on SFTP, cloud or `node://` paths; it starts there only when asked.
  - Local folders that are not library sources start it on their own only when **Settings → General → Folder sizes in local folders** is on (default off: walking a big tree costs disk time).
- **Details:** the Size column shows a folder's total when it is known, `…` while it is being computed, and stays empty when unknown. Sorting by size puts known totals in order and unknown ones last. The status bar shows the selected folders' total when known.
- **Sizes view:** a view button next to Media.
  - The children are sorted by size, each with a bar for its share of the folder, its file count, and its share of the volume's used space (from the drive's numbers).
  - Enter goes down, Backspace up.
  - It reuses the details rows with a bar column. No treemap; add one if asked.
- **API:** a `library.folder_sizes { path }` operation (read-only) in `keel-api`, so the web client and agents can ask, and `keel du <path>` on the CLI. Document both in `docs/api.md`.
- **Counting:** apparent sizes (a file's length). Hard links count once per path, and cloud placeholders by their stated size. Say so in the docs.

**Tests:**
- Unit tests of the totals on a fixture tree, after add, remove, a rename within a folder, a move across folders, a burst of 10,000 changes, and source removal.
- A perf test: 200,000 files in 20,200 folders, totals within budget.
- A walkthrough flow: the Sizes view renders and sorts, Enter and Backspace move through it, and Calculate sizes can be cancelled.
- An API test of `library.folder_sizes`.
- **Live (Windows desktop):** generate a tree in a temporary folder with known sizes. Compare Keel's totals with `(Get-ChildItem -Recurse -File | Measure-Object -Sum Length).Sum` for each subfolder. Then open the Sizes view on a system folder such as `C:\Windows\Fonts` to judge speed. Screenshots only of the generated tree.

**Docs:**
- `docs/files.md`: a section, "Folder sizes and the Sizes view".
- `docs/library.md`: totals are kept with the index.
- `docs/getting-started.md`, `docs/features.md`, `docs/api.md`, `docs/performance.md`.
- CHANGELOG.

**Commits:**
- `feat(core): folder totals kept with the index`
- `feat(app): folder sizes in Details and a Sizes view`
- `feat(api): library.folder_sizes and keel du`
- `docs: folder sizes`

### Task 47: color themes (worktree `task47`)

**Goal:** Spec section 1 asks for color themes, and Atlas sells "rich color themes"; Keel has dark and light. Add a set of built-in themes, a picker, and installing a VS Code color theme from the Marketplace, the same way icon themes install.

**Read:**
- `crates/keel-app/src/theme.rs` (a `Theme` is six colors: `bg`, `panel`, `text`, `accent`, `selection`, `muted`; the WCAG test `builtin_themes_meet_wcag_contrast`).
- `assets/themes/*.toml`.
- `crates/keel-app/src/icon_theme.rs`: the Marketplace download, the license shown before install, the size caps. Reuse it rather than copy it.
- `settings.rs`, and the Icon themes section of `docs/files.md`.

**Design points:**
- **Built-in themes:** add four themes of Keel's own, with generic names, for example Midnight, Paper, Dusk and High contrast. Each must pass the existing 4.5:1 contrast test. The warning and error colors added in 0.17.0 become optional theme fields, with the current values as defaults.
- **Picker:** Settings → General → Theme lists the built-ins and every `<config>/themes/*.toml`, under any name. Today a user file can only override `dark` or `light`. The change applies at once, and the choice is saved per profile.
- **VS Code color themes:**
  - **Install:** type `publisher.name`, then **Install from VS Code Marketplace…**. The license is shown with **I accept**, and the package is unpacked into the config folder, as for icon themes. Only JSON is read: no code runs, nothing is fetched beyond the package, and the size caps are the same.
  - **Parse:** read `contributes.themes` from `package.json`; a package can hold several themes, and each is listed. Theme files are JSON with comments and trailing commas, and may `include` a parent theme (follow at most 4 levels, inside the package only).
  - **Map onto Keel's colors:**

    | Keel color | VS Code key, first one present |
    | --- | --- |
    | `bg` | `editor.background` |
    | `panel` | `sideBarSectionHeader.background`, then `sideBar.background`, then `panel.background` |
    | `text` | `foreground`, then `editor.foreground` |
    | `accent` | `focusBorder`, then `button.background`, then `textLink.foreground` |
    | `selection` | `list.activeSelectionBackground` |
    | `muted` | `descriptionForeground`, then `disabledForeground` |

  - `uiTheme: "vs"` means a light theme; anything else is dark. Missing keys fall back to the built-in dark or light value, and alpha is flattened against `bg`.
  - **Contrast:** a theme whose text or muted color is under 4.5:1 against `bg` or `panel` has that color moved toward legibility. The picker says "adjusted for contrast", so Keel keeps its accessibility promise with any theme.
- Keel never bundles or redistributes Marketplace themes, as with icon themes.

**Tests:**
- Mapping tests with a hand-written fixture theme (not a copy of a real one), including comments, trailing commas, an `include` chain, a missing key, an alpha color, and a light theme.
- Cycles and a too-deep `include` are refused.
- The contrast adjustment brings a low-contrast theme to 4.5:1.
- The WCAG test covers every built-in.
- A fuzz target for the theme JSON parser.
- kittest screenshots of each built-in on the fixture.
- **Live (Windows desktop):** install one MIT-licensed color theme from the Marketplace through the dialog, switch to it, and check the window and Settings. Then remove it. Screenshots only through `scripts/screenshots.sh`.

**Docs:**
- `docs/files.md`: a section, "Color themes", beside Icon themes.
- `docs/getting-started.md`: Profiles, themes and icon themes.
- `docs/features.md`: the Themes bullet.
- README: the features line.
- CHANGELOG.

**Commits:**
- `feat(app): built-in color themes and a theme picker`
- `feat(app): install VS Code color themes from the Marketplace`
- `docs: color themes`

## Needs the owner

These cannot be done by a worker alone: they need money, accounts, a licensing decision or hardware.

| Item | Why | Blocks |
| --- | --- | --- |
| Code-signing certificates: Windows Authenticode, and an Apple Developer ID ($99 a year) | money, identity checks | signed releases ([releasing.md](../../releasing.md)); friends' SmartScreen and Gatekeeper prompts (parity gap #10) |
| Package channels: a winget-pkgs pull request, a Homebrew tap, Flathub or AppImage | submissions under the owner's GitHub account; Flathub review | gap #10 |
| Mounts in the Windows release | winfsp-rs is GPL-3.0. Ship a separately licensed GPL `keel-daemon` download, keep build-from-source, or find another backend: a licensing decision | gap #9 |
| Mounts in the macOS release | macFUSE cannot be installed on the CI build machines: a self-hosted Mac runner, or leave it | gap #9 |
| HEVC Video Extensions from the Microsoft Store (paid) | only if Task 45 later adds the Windows WIC path; the plan uses ffmpeg, so not needed now | none in this phase |
| WSL installed on the desktop (administrator) | the live check of WSL integration | gap #8 (Phase 11) |
| Live runs on the owner's Mac and Linux machines | hardware; Tasks 44 and 45 ask for a Mac run | Task 44 and 45 live checks |
| Accepting each Marketplace license during the Task 47 live check | the owner's click, as for icon themes | Task 47 live check |
| Atlas: the free alpha on 2026-10-23 (no purchase needed) | re-running the Atlas rows against a real build | Task 48 parity refresh |

Not needed: buying an Atlas preorder or Spacedrive's paid app. Their features are listed in [docs/parity.md](../../parity.md) from public pages.
