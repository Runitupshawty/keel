# Keel Phase 4 Implementation Plan: cloud storage as folders

> **For agentic workers:** same rules as the Phase 2 and 3 plan headers. Read spec 2.1 (cloud providers), 2.10 (cloud via opendal), 2.9, the Phase 1 Global Constraints + Amendments, and the Phase 3 plan (RemoteHost / transfer / sidebar patterns, which cloud reuses).

**Goal:** Google Drive, Dropbox and any S3-compatible bucket (Backblaze B2, AWS, MinIO) appear in the sidebar as folders; browse, preview, open-with (materialised), upload/download via the normal copy/move flow, rename/mkdir/delete. iCloud is NOT a provider here (it is reached through the Mac mini over SFTP). OneDrive is never added.

**Design:** one `CloudProvider` over `opendal` (`services-gdrive`, `services-dropbox`, `services-s3`) so listing/read/write are uniform; OAuth for Google Drive and Dropbox uses the loopback redirect flow (PKCE, no client secret in the binary) with a browser hand-off; tokens live in the OS keychain (`keyring`), never in config; only non-secret metadata (account label, provider, root folder id, client id override) is in `config.toml` under `[[clouds]]`. Keel ships default public client ids in `assets/cloud-clients.toml`; users may override. Listings are cached per folder for 60 s; writes invalidate.

**Review focus:** (1) tokens never land in config, logs, toasts or crash.log; (2) refresh-token rotation and revoked-token handling (re-auth prompt, not a crash); (3) rate limits (429) back off, never spin; (4) Drive "same name twice" and shortcuts; (5) uploads are atomic from the user's view (temp name then rename, or resumable upload then commit); (6) S3 listing with 100k keys pages lazily.

### Task 18: `keel-vfs` cloud provider (worktree `task18`)

**Deps:** `opendal = { version = "0.52", features = ["services-gdrive", "services-dropbox", "services-s3"] }`, `oauth2 = "5"`, `tiny_http` or `axum` minimal loopback listener (prefer `tiny_http`), `keyring = "3"`, `open = "5"` (browser), tokio runtime shared with the sftp module.

**Interfaces (Produces):**
```rust
#[derive(Clone, Debug, PartialEq, serde::Serialize, serde::Deserialize)]
pub struct CloudAccount { pub id: String, pub label: String, pub kind: CloudKind, pub root: Option<String>, pub client_id_override: Option<String> }
#[derive(Clone, Copy, Debug, PartialEq, serde::Serialize, serde::Deserialize)] pub enum CloudKind { GoogleDrive, Dropbox, S3 }
#[derive(Clone, Debug, PartialEq, serde::Serialize, serde::Deserialize)] pub struct S3Config { pub endpoint: String, pub region: String, pub bucket: String, pub access_key_in_keyring: bool /* secret always in keyring */ }
pub struct CloudProvider { account: CloudAccount, op: opendal::Operator, .. }
impl CloudProvider { pub fn connect(account: &CloudAccount, secrets: &dyn SecretStore, events: Sender<RemoteEvent>) -> Result<Self>; }
pub trait SecretStore: Send + Sync { fn get(&self, key: &str) -> Result<Option<String>>; fn set(&self, key: &str, value: &str) -> Result<()>; fn delete(&self, key: &str) -> Result<()>; }
pub struct KeyringStore; impl SecretStore for KeyringStore { .. }   // service "keel", account "<cloud id>/<field>"
pub fn oauth_authorize(kind: CloudKind, client_id: &str, events: Sender<RemoteEvent>) -> Result<OAuthTokens>; // opens the browser, listens on 127.0.0.1:<random>, PKCE, 120 s timeout, cancellable
pub struct OAuthTokens { pub access: String, pub refresh: Option<String>, pub expires_at: SystemTime }
impl Provider for CloudProvider { /* scheme "cloud"; authority = account id; list/stat/read/write/create_new/mkdir/rename/remove; local_copy_with_progress like sftp; Caps { delete: true, .. }; remove = provider trash where the API has one (Drive: trash, Dropbox: delete is recoverable 30 days, S3: hard delete after confirm) */ }
```

**Steps:** (1) config + secret-store round-trip tests (fake store in tests; `KeyringStore` integration test `#[ignore]`); (2) OAuth loopback flow unit-tested with a fake authorization server (local `tiny_http` that redirects immediately); (3) opendal operator construction per kind; (4) list with 60 s cache + pagination; (5) read/write/create_new/mkdir/rename/remove with temp-then-rename uploads; (6) 429/5xx backoff with jitter, max 5 tries; (7) `transfer` works cloud↔local and cloud↔sftp through staging; (8) live tests behind `KEEL_CLOUD_TEST_S3=endpoint,region,bucket` (James's B2 bucket via env only) and `KEEL_CLOUD_TEST_GDRIVE=1` (interactive, `#[ignore]`); commit `feat(vfs): cloud provider (Google Drive, Dropbox, S3) over opendal with keychain-held tokens`.

### Task 19: app integration of cloud (worktree `task19`, after 18 and Phase 3 app merge)

- Tests: wizard state machine; config round-trip; sidebar model; transfer job with the local provider standing in.
- Commit `feat(app): cloud accounts in sidebar and settings, sign-in wizard`.
