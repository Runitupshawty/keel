# Keel Phase 15 Implementation Plan: Everything parity, the search engine

> **For agentic workers:** same rules as earlier plan headers. Read [the audit](2026-10-12-everything-windirstat-audit.md) first: Part 1 lists every Everything feature from voidtools' own pages, Parts 2 and 3 say what Keel has, with files and lines. Each task gets its own worktree, branched from the release Phase 15 starts on. Run `cargo fmt --all --check`, `cargo clippy --all-targets -- -D warnings` and the tests of the crates touched before every commit. Any new parser of outside bytes (MFT records, USN records, file signatures, EFU, property readers) gets a fuzz target (see [docs/fuzzing.md](../../fuzzing.md)). Every user-visible change goes into the docs and the CHANGELOG in the same task. Public repo: no hostnames, IPs, user names, personal names or personal paths in code, tests, fixtures, screenshots or commit messages.

**Goal:** Keel's own engine does everything voidtools Everything does, on every platform, without Everything installed: an index of every file on every volume with size, size on disk, all dates, attributes and folder sizes, kept live, loaded instantly, sorted instantly by any column; and the complete Everything search language (every operator, all 49 modifiers, every search function in Part 1, date and size constants, macros and filters) used by one parser for the pane search, library search, the CLI, the API and MCP. Everything stays a supported backend; when it runs, Keel still passes queries through, and Keel-only terms keep working.

**Not in this phase:** the search UI (toggles, filters, bookmarks, history, columns, omissions UI), file lists, the HTTP/ETP servers, `es`-compatible CLI and the SDK are Phase 16. Disk-usage views are Phase 17 (they reuse this phase's index).

**Live checks.** On the owner's Windows desktop with fixtures in a temporary folder, a VHDX created and mounted for NTFS/ReFS/FAT/exFAT volume tests (removed after), and `KEEL_CONFIG_DIR`, `KEEL_DATA_DIR` and `KEEL_NET_SECRET=memory` set first in every command. Timing against Everything 1.4 on the same machine is recorded in `docs/performance.md`: index build of the system drive, load at start, a substring query over all files, sort by size and by date modified.

**Review focus:**
1. The elevated part stays tiny: only the raw volume read runs elevated (the existing `--index-service` helper or the new service), it parses nothing it does not need, and everything it hands back is re-validated by the unelevated process. The MFT and USN parsers are fuzzed and never panic on hostile bytes.
2. The index never shows a file the user cannot list in Explorer: per-user filtering of entries in folders the user cannot read (ACL check on folder entry, cached), on by default, documented.
3. A query is bounded: regex compile size and time limits, `from-disk:` and content functions capped in files and seconds, dupe and descendant functions bounded in memory, and a typed query can never hang the UI (the worker drops stale queries as today).
4. Parity is checked, not claimed: a conformance test file `crates/keel-query/tests/everything.rs` holds one case per function and modifier in Part 1, with the expected result on a fixture tree, and the docs table is generated from it.
5. Memory: the index of a 5-million-entry volume stays within 2x Everything's measured RAM on the same volume.

### Task 70: the full-metadata index (worktree `task70`)

**Read:** `crates/keel-search/src/ntfs/{mod,win,usn,db,index,pattern}.rs`, `walkindex.rs`, `composite.rs`, `everything.rs`, `lib.rs` (`Query`, `Hit`, `Searcher`); `docs/files.md` (Search without Everything); the audit Part 2.

**Design points:**
- **Raw MFT reader** (`ntfs/mft.rs`): read `$MFT` through the volume handle in the elevated helper, parse FILE records (fixups, attribute list, `$STANDARD_INFORMATION` dates and attributes, every `$FILE_NAME` for hard links, `$DATA` real and allocated size for the unnamed stream, named streams counted for ADS, reparse tag). Falls back to today's `FSCTL_ENUM_USN_DATA` plus per-entry stat when the raw read is refused. Fuzz target `mft_record`.
- **Record columns** stored as structure-of-arrays: frn, parent, name (shared buffer), size, allocated size, date created, modified, accessed, recently changed (the USN time of the last change Keel saw), attributes, hard link count, ADS count, reparse tag, run count, date run, and folder aggregates (total size, allocated, file count, folder count, newest change below) rolled up on build and kept current on each USN batch. Everything's "Indexes" tab options become Settings → Search → **Indexed properties** (file size, folder size, created, modified, accessed, attributes, each with **Fast sort**).
- **Fast sort:** a precomputed permutation per enabled column (and by extension), updated incrementally; sorting any result set by an indexed column is then a filter over the permutation, not a sort.
- **USN live updates** use the record's own timestamp and attributes, and fetch size/dates for changed files with `OpenFileById` (helper or service) or a path stat; **Monitor changes** can pause and resume (`-monitor-pause`). **Load recent changes from the USN journal** at start fills `rc:` for changes made while Keel was closed. USN journal options from Everything's NTFS tab: enable, maximum size, allocation delta, create/delete journal (helper only, explicit button).
- **Volumes:** NTFS and ReFS through the USN path (ReFS has no MFT; enumerate with `FSCTL_ENUM_USN_DATA` + stat); FAT, exFAT and network drives through a folder-scan index with change monitoring (`ReadDirectoryChangesW`), buffer size, **rescan on full buffer**, a rescan schedule (every N hours or daily at a time) and **Fast rescan** (only folders whose mtime moved); **Folders** list for arbitrary folders (any platform, any VFS provider that lists). **Automatically include new fixed / removable volumes**, **Automatically remove offline volumes** (off: offline volumes stay searchable, marked offline, Everything 1.5 behavior), **Include in database / Include only** per volume.
- **Exclude tab:** exclude hidden, exclude system, exclude folders (list), include only folders, include only files (wildcards), exclude files (wildcards), applied at index time.
- **macOS and Linux:** the same columns from a parallel walk plus FSEvents / fanotify-or-inotify; on Linux with `CAP_SYS_ADMIN` available through the helper, fanotify on the whole mount. Spotlight and `locate` stay as backends but the own index becomes the default, since it supports the whole language.
- **Database** saved with a version, written atomically, loaded with `mmap` so start is instant (measure: under 1 s for 2 million entries); **Force rebuild**; database location setting; per-user database file (`multi-user database filename`).
- **Index service:** `keel --install-service` installs a `KeelIndex` Windows service (LocalSystem, demand start, named pipe with a per-user ACL) that does the elevated reads, so non-admin users get the full index with no UAC prompt after install, like the Everything Service; `--index-as-admin` keeps today's one-shot helper. Uninstall removes it.

**Tests:** MFT parser against fixture records (normal, fragmented attribute list, hard links, ADS, sparse, compressed, reparse points, corrupt fixups); a VHDX live test builds the index and compares every column to `GetFileInformationByHandleEx`; USN replay updates size and folder totals; fast sort permutations stay correct after 10,000 random renames/deletes; per-user ACL filtering; load time benchmark.

**Docs:** `docs/files.md` (Search: the index, what it stores, the service, volumes, excludes), `docs/performance.md`, CHANGELOG.

**Commits:** `feat(search): raw MFT reader`, `feat(search): full-metadata index with folder aggregates and fast sort`, `feat(search): ReFS, FAT, exFAT, network and folder indexes`, `feat(search): Keel index service`, `docs: the index`

### Task 71: one query language (worktree `task71`, new crate `keel-query`)

**Read:** `crates/keel-search/src/ntfs/pattern.rs` and `walkindex.rs:569-640` (the two copies of the native parser), `crates/keel-core/src/search.rs` (`LibraryQuery::parse`, SQL filters), `chips.rs`, the audit Part 1 (Search syntax, modifiers, functions) and Part 3 (Planner facts).

**Design points:**
- **Grammar** (Everything's, exactly): space = AND, `|` = OR, `!` = NOT, `< >` grouping, `"quotes"`, `*` and `?` wildcards (whole-filename match when **Match whole filename when using wildcards** is on), `\` in a term searches paths, trailing `\` matches folders, `..` and `-` ranges, `;` lists, comparison operators `<= < = == > >= != !`, `unknown`, `function*:` for literal text, `$property:` substitution and `$0:`..`$9:` regex captures, **Allow literal operators**, **Replace forward slashes with backslashes**, **operator precedence** (AND or OR first; `and-precedence:`, `or-precedence:`).
- **All 49 modifiers** from Part 1 with Everything's meaning, each with its `no-` form and aliases: case, diacritics, whole-words, path, prefix, suffix, start-with (`^:`), end-with (`$:`), whole (wfn/entire), regex, wildcards, file, folder, ignore-punctuation, ignore-whitespace, len, metric, hex, hex-to-number, binary, to-integer/to-number/to-string, multi-string, all-strings, each-line, multi-line, dot-all, ungreedy, global, star-all, soundex, pinyin/pinyin-jian/pinyin-quan, no-substitute, no-fast-regex, no-highlight, from-disk, no-reorder, search-current-results, and-filter, or-filter, enable/disable-result-omissions and the temporary forms, no-!, and the UI-only menu-break and menu-separator (accepted, used by Phase 16 filter menus).
- **Search functions:** every name and alias in Part 1 (name/path/type, size/count, the dates with their -date/-day/-day-of-week/-hour/-month/-time/-year forms, attributes and file info, duplicates, image, audio/video/music, document, UI-state), plus the legacy aliases Keel's users may type from Everything 1.4 (`sizedupe:`, `namepartdupe:`, `dmdupe:`, `infolder:`, `nosubfolders:`, `runcount:`, `daterun:`, `utf8content:`, `ansicontent:`, `utf16content:`) mapped to their current forms. Functions are evaluated through a `Props` trait: indexed properties are O(1) column reads; the rest are computed lazily (Task 73) and only for candidates that pass the cheap terms first (the evaluator reorders terms by cost unless `no-reorder:`).
- **Constants:** dates (today, yesterday, tomorrow, thisweek/lastweek/nextweek, thismonth/lastmonth, thisyear/lastyear, pastNhours/days/weeks/months/years, month names, weekday names, times of day, ISO-8601 with wildcards, local formats per the OS locale); sizes (empty, tiny < 10 KB, small < 100 KB, medium < 1 MB, large < 16 MB, huge < 128 MB, gigantic > 128 MB, with Everything's exact bounds), units with `metric:` choosing 1000 or 1024.
- **Macros and filters:** the built-in filter macros `audio:`, `zip:`, `doc:`, `exe:`, `pic:`/`image:`, `video:` with Everything's extension lists; user filters (Phase 16 UI) and bookmarks are macros too (`filter-name:`), stored per profile.
- **Library terms** stay: `tag:`, `content:` (FTS), `camera:`, `taken:`, `has:gps`, `kind:photo`, `contents:`, `in:` (now a path or a source, fixing the documented mismatch), `source:`, `is:favorite`, `is:recent`. The evaluator compiles what it can into SQL for library stores and post-filters the rest.
- **Everything passthrough:** when the Everything backend is active, Keel rewrites Keel-only terms (`in:`, `tag:`, `source:`) into Everything syntax or a post-filter, and passes everything else unchanged; **Search with Keel's index** is a per-tab switch.
- The pane, library, CLI (`keel search`), API (`search`, new `system.search`) and MCP all call `keel_query::parse` and share errors (position + message), shown inline under the search field.

**Tests:** the conformance file (one test per operator, modifier, function, alias and constant against a fixture tree with known sizes, dates, attributes, hard links, ADS and media); precedence and grouping cases; fuzz target `query_parse`; regex limits; old library query tests all still pass.

**Docs:** `docs/search.md` (new: the full language reference, generated tables from the conformance file), `docs/library.md` and `docs/files.md` point to it, CHANGELOG.

**Commits:** `feat(query): parser and evaluator`, `feat(query): modifiers`, `feat(query): search functions`, `feat(query): date and size constants, macros`, `refactor(search,core): use keel-query everywhere`, `docs: search language reference`

### Task 72: tree, duplicate and set functions (worktree `task72`)

**Design points:**
- Tree functions over the index's parent links: `parent:`, `parent-name:`, `parent-count:`/`depth:`, `root:`, `ancestor:`, `ancestor-name:`, `child:`, `child-file:`, `child-folder:`, `child-count:`, `child-file-count:`, `child-folder-count:`, `descendant:` (+ file/folder/count forms), `sibling:` (+ file/folder), `parent-sibling`, `ancestor-sibling`, `empty:`, `exists:`, `count:`, `parentsize`, `parentdm`, `pathlist:`; counts come from the folder aggregates, matches from a bounded subtree scan.
- Duplicate and set functions: `dupe:` on any property list (`dupe:size;name`), `dupe-count:`, `dupe-from:`, `dupe-min:`, `dupe-max:`, `distinct:`, `distinct-sort:`, `unique:`; hash dupes use the library's BLAKE3 ids when present, else compute (bounded, cancelable).
- Hard link functions: `hard-link-count:`, `hard-link-filenames:`; ADS: `alternate-data-stream-count:`, `alternate-data-stream-names:`; containers: `container-file-count:`, `container-filenames:` (archives, through `keel-vfs` archive listing, bounded).

**Tests:** each function on the fixture tree; a 1-million-entry synthetic index answers `dupe:size` in under 2 s and `child-count:>1000` in under 1 s.

**Commits:** `feat(query): tree functions`, `feat(query): dupe, distinct and unique`, `feat(query): hard links, streams and containers`, `docs: tree and duplicate functions`

### Task 73: properties beyond the index (worktree `task73`)

**Design points:**
- A **property system** (`keel-props` module): Windows Property System (`IPropertyStore` via `SHGetPropertyStoreFromParsingName`) for any of the media, document and executable properties in Part 1; on macOS `MDItem` attributes; on Linux and as a fallback, Keel's own readers (`lofty` for audio tags, the existing EXIF/video sidecars, PE version resources via `pelite`, Office core properties). Every function in Part 1's image, audio/video/music and document groups maps to one property; unknown on a platform means "unknown" (matches `unknown`).
- **Property indexing** (Everything 1.5 Properties tab): choose properties to index, include/exclude folders and files, include-only, exclude not-content-indexed, **exclude recall on data access** (never hydrate cloud placeholders), maximum file size, fast sort per property. An idle job like the library's sidecar job fills them.
- **Content:** `content:` over any file (not only library sources) with `utf8content:`, `utf16content:`, `utf16becontent:`, `ansicontent:`, `binary:`, `hex:`, `each-line:`, `multi-line:`; capped by size and time; uses the library's extracted text when the file is in a source. Content indexing as an option per folder (Everything 1.5).
- **File info:** `perceived-type:`, `content-type:`, `file-signature:` (magic bytes, fuzz target), `shortcut-target:` (.lnk and symlinks; .lnk parser fuzzed), `volume-label:`, `location:`, `computer:`, `url:`, `owner:`, `protected:`, `offline:`/`online:`/`offline-availability:`/`offline-status:` (cloud placeholder states via `CfGetPlaceholderStateFromAttributeTag`), `shared-with:`, `status:`, `content-status:`, `character-encoding:`, `line-count:`, `word-count:`, `page-count:`, `slide-count:`, `total-editing-time:`, `version:`, `product-name:`, `product-version:`, `company:`, `copyright:`, `trademarks:`, `description:`, `details:`, `digital-signature-name:`, `digital-signature-timestamp:` (`WinVerifyTrust`), hashes `md5:`, `sha1:`, `sha256:`, `crc32:`, `crc64:`, plus sidecar hash and folder hash properties; `date-deleted:` (Recycle Bin items), the other Part 1 dates where a property exists.
- **Run tracking:** `run-count:`, `date-run:`, `is-running:` (process list): Keel counts every open it performs (any file, not only library ones), with **Run history** in Settings (clear, off); `es`-style get/set/increment through the API in Phase 16.
- **Windows Search:** `system-index:` / `si:` runs the query through the Windows Search index (OLE DB `Search.CollatorDSO`) and merges.
- `soundex:` and `pinyin:` matching (pinyin table from `pinyin` crate, MIT).

**Tests:** each property against fixtures per platform (CI matrix), cloud placeholders never hydrated (a test with a fake CfApi provider on Windows CI), content caps, signature check on a signed and an unsigned exe.

**Commits:** `feat(props): property system`, `feat(search): property indexing`, `feat(query): content functions`, `feat(query): file info, hashes and signatures`, `feat(search): run history`, `docs: properties`

### Task 74: the index journal and recent changes (worktree `task74`)

**Design points:**
- **Journal** (Everything 1.5 Index Journal): every create, delete, rename, modify and attribute change the index applies is appended to a bounded on-disk journal (size setting, default 64 MB), with old and new path and the USN time. Shown in a **Journal** tab (filters by action, date range, path regex, "changed today"), searchable, exportable; `keel journal --watch` streams it (Phase 16 adds `es -journal`).
- `rc:` / `date-recently-changed:` and **Index recent changes** use it; the Inspector shows a file's journal entries next to Keel's own history.
- **Result omissions** at the engine level: omitted paths and temporary omissions per profile, honored unless `disable-result-omissions:`.

**Tests:** journal entries for each action on a VHDX, rotation at the size cap, journal survives restart, omissions on and off.

**Commits:** `feat(search): index journal`, `feat(search): result omissions`, `docs: journal and omissions`
