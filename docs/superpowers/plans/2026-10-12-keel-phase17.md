# Keel Phase 17 Implementation Plan: WinDirStat parity, disk usage

> **For agentic workers:** same rules as earlier plan headers. Read [the audit](2026-10-12-everything-windirstat-audit.md) Part 1 section 2 (WinDirStat, checked against its 2.9.3 changelog and README) and Part 4 (Keel's state, with the Planner facts on how the Sizes view, folder totals and jobs work) first. Phase 15's raw MFT reader (Task 70) makes elevated scans fast; tasks here fall back to a parallel walk without it, so they can start before Phase 15 lands. Each task gets its own worktree. Run `cargo fmt --all --check`, `cargo clippy --all-targets -- -D warnings` and the tests of the crates touched before every commit. Every parser of on-disk structures (deleted-file recovery, MTP, scan files) gets a fuzz target. Every user-visible change goes into the docs and the CHANGELOG in the same task. Public repo: no hostnames, IPs, user names, personal names or personal paths anywhere.

**Goal:** A **Disk Usage** window (and view mode) that does everything WinDirStat 2.x does: scan drives, folders, shares and phones fast and in parallel; a directory tree with subtree bars and every column; a file-types list; a cushion treemap with all of WinDirStat's layouts and options, a sunburst and a flame graph, all selection-linked; Largest files, Duplicates, Search, Storage analytics and Permissions tabs; every cleanup, user-defined cleanups and deleted-file recovery; CSV/JSON export and load; and the command line for unattended reports.

**Live checks.** As Phase 15, with VHDX volumes for NTFS/exFAT/FAT recovery tests (files written, deleted, recovered to another volume, VHDX removed). Destructive cleanups (delete permanently, hibernation, VHD optimize, compression) are only run live inside the VHDX or temp folders, never on the owner's real drives.

**Review focus:**
1. Every destructive action goes through a preview and a confirmation that names the bytes and paths; permanent delete and the system cleanups (hibernation, DISM, VHD) need an explicit second confirmation and are never on a default key; user-defined cleanups show the expanded command before the first run.
2. Recovery never writes to the volume it recovers from, opens the volume read-only, and its parsers never panic on hostile bytes.
3. Scans never hydrate cloud placeholders, never follow links unless the option says so, and count hard links once when **Count hard links once** is on (the default).
4. A 2-million-file drive scans in under 60 s without the MFT path and under 10 s with it, and the treemap stays interactive (under 16 ms per frame after the first render).
5. Everything in this window is reachable by keyboard and has accessible names; the treemap has a text equivalent (the tree list, synced).

### Task 81: the scan engine (worktree `task81`)

**Read:** `crates/keel-vfs/src/sizes.rs`, `crates/keel-app/src/sizes.rs`, `jobs.rs` (`folder_sizes`, `spawn`), `crates/keel-core/src/totals.rs`, `fsid.rs`, `hash.rs:1117-1170`, the audit Part 4 Planner facts.

**Design points:**
- A `keel-du` module (in `keel-vfs`): scan one or many roots (drives, folders, network shares, the **All local drives** choice, and on Windows MTP phones and cameras through WPD) into one tree of nodes `{name, parent, size, allocated, files, folders, items, newest change, attributes, owner (lazy), ext id, hard-link id}`; per-drive parallel walking with a work-stealing pool (`rayon` or `jwalk`), and the raw MFT path (Phase 15 Task 70) when elevated or the index service runs; long paths and `\\?\Volume{GUID}`.
- **Size on disk:** `GetCompressedFileSizeW` (compressed and sparse), cluster rounding, `st_blocks * 512` on Unix; sparse and compressed flags kept for the list.
- **Hard links:** counted once by `fs_id` (**Count hard links once**, default on); **Reparse points:** options to follow junctions, mount points, symlinks (each off by default) and to exclude reparse points.
- **Filters:** exclude by path, name, regex on the path, minimum size, age (older/newer than), include filters, exclude hidden, exclude system, exclude cloud-ignored items (Dropbox `com.dropbox.ignored`), size and age comparisons (`>`, `<`); filter actions from the context menu ("Exclude this folder from scans").
- **Elevation:** "Relaunch elevated" for scans that hit access denied, with backup/restore privileges used when elevated so protected folders are read; eligibility detection.
- **Pause, resume, cancel, refresh all, refresh selected branch** (rescan one node only).
- **Progress:** files and bytes per second, current path, elapsed time and total time when done, and an animated indicator (Keel's own, Reduce motion respected; WinDirStat's pacman is its trademark look, not copied).
- **Process priority:** CPU and I/O priority setting for scans.
- **Free and unknown space** pseudo items per drive (unknown = used − scanned).
- **Scan files:** save and load a scan (JSON, versioned, compressed), so a scan opens instantly later; previous-folder history with pruning.
- **File Watcher** (WinDirStat 2.8): after a scan, watch the roots and apply changes live, with toolbar controls (pause, clear) and a live regex path filter on the change list.

**Tests:** fixture trees with hard links, sparse and compressed files (VHDX live), junction loops, filters, pause/resume, refresh-branch, save/load round-trip, watcher updates totals, scan of a 1-million-file synthetic tree benchmarked.

**Commits:** `feat(vfs): parallel multi-root scan with size on disk`, `feat(vfs): hard links, reparse points and filters`, `feat(vfs): scan files and file watcher`, `feat(vfs): MTP scan on Windows`, `docs: disk usage scans`

### Task 82: the Disk Usage window and tree list (worktree `task82`)

**Read:** `view_details.rs` (Sizes mode, `share_bar`), `pane.rs` (`ViewMode`), `tab.rs`, `inspector.rs`, `sidebar.rs` (drives).

**Design points:**
- A **Disk Usage** window (Ctrl+Shift+U, palette, a drive's context menu "Analyze disk usage", and the Explorer folder context menu entry "Analyze with Keel", per-user registration) and a **Disk usage** view mode in a pane; a **Select drives** dialog (each drive with used/free bars, all local drives, a folder picker, multi-folder selection, double-click scans).
- **Layouts:** WinDirStat's (tree top-left, file types top-right, treemap below) and alternatives from a layout chooser (treemap left, tabs only, etc.), splitters remembered.
- **Tree list:** expandable tree, subtree percentage bar colored by depth, columns Name, Subtree %, Percentage (absolute or relative mode), Size, Size on disk, Items, Files, Folders, Last change (newest in the subtree), Attributes, Owner, Last accessed, Created; column chooser by right-clicking the header; sort by any; multi-select with the selection's size sum in the status bar; tooltips with size proportions; logical vs physical size switch; grid and stripes options; seconds in timestamps option.
- **File types list:** color swatch, extension, description (from the OS: `AssocQueryString` / UTType / shared-mime-info), bytes, %, files; **group unregistered extensions**; double-click searches that extension in the tree (and opens a search tab).
- **Selection sync** across tree, file types, treemap, sunburst and flame graph.
- The existing Sizes view stays as the lightweight in-pane view; it gains Size on disk and Items columns from this task's scan.

**Commits:** `feat(app): disk usage window and drive picker`, `feat(app): disk usage tree list`, `feat(app): file types list`, `docs: disk usage window`

### Task 83: treemap, sunburst and flame graph (worktree `task83`)

**Design points:**
- **Treemap** renderer (`keel-app/src/treemap/`): layout off-thread (squarified by default; WinDirStat's simple strip layout; **Hilbert** and **Moore** space-filling layouts), cushion shading after van Wijk and van de Wetering rasterized on a worker into a texture (flat mode drawn as one `egui::Mesh`), hit-testing by the layout rectangles.
- **Options:** brightness, cushion height, scale factor, light source position (drag a point), ambient light, grid on/off and color, **folder frames** with colors and a draw threshold, colors per extension (WinDirStat's 13-color cycle by size rank, editable), **style presets** (KDirStat, SequoiaView, WinDirStat, flat), reset.
- **Interaction:** hover tooltip (path, size, %), click selects in the tree, double-click zooms into a folder, zoom out (Backspace / mouse back), Ctrl+wheel zoom, keyboard arrows move between neighbors, highlight the selection and all files of the selected extension.
- **Sunburst** and **flame graph** views of the same tree (WinDirStat 2.8) with free/unknown labels, same selection and zoom.
- Show/hide treemap, file types, free space, unknown space (View menu).

**Tests:** layout invariants (areas proportional within 0.5%, no overlap, all inside), Hilbert/Moore order, hit-test, render benchmark (200,000 tiles under 200 ms first render, 16 ms per frame after), snapshot tests per preset.

**Commits:** `feat(app): treemap layouts`, `feat(app): cushion shading and options`, `feat(app): sunburst and flame graph`, `docs: treemap`

### Task 84: the analysis tabs (worktree `task84`)

**Design points:**
- **Largest files:** top N across the scan (N setting, size range filter), with path, size, size on disk, modified; jump to tree.
- **Duplicates** inside the scan (works outside the library): size grouping, then partial hash, then full hash; hash algorithm setting (BLAKE3 default, xxHash3, SHA-256), **sparse hashing** for files over 64 MiB marked "Probable duplicates", never reads cloud placeholders; cancelable progress; actions Keep this one, replace with hard links (same volume, preview), delete others; save the list as CSV/JSON; extension column. When the files are in a library source, the library's BLAKE3 ids are reused.
- **Search** tab: by name (substring or regex), size range, item type, owner; totals of the results; uses `keel-query` when Phase 15 has landed.
- **Storage analytics:** user-defined storage tiers with cost per GB, files bucketed by modification age (e.g. hot < 30 days, warm < 1 year, cold), totals and estimated monthly cost per tier, per extension and per top folder.
- **Permissions:** scan ACLs (Windows) or owner/mode (Unix) per folder, explicit vs inherited entries, broken inheritance highlighted, everyone/world-writable flagged; export CSV.

**Commits:** `feat(app): largest files`, `feat(app): duplicates in disk usage`, `feat(app): disk usage search`, `feat(app): storage analytics`, `feat(app): permissions scan`, `docs: analysis tabs`

### Task 85: cleanups (worktree `task85`)

**Design points:**
- Standard actions on any node (most exist in panes; reuse them): open, open with, show in Explorer/Finder, terminal here (Keel's pane or an external console, setting), copy path, properties/Get Info, move to…, delete to Recycle Bin, **delete permanently** (new; review focus 1), empty Recycle Bin, refresh selected.
- **NTFS compression:** compress / uncompress with LZNT1 (`FSCTL_SET_COMPRESSION`) or WOF XPRESS4K, XPRESS8K, XPRESS16K, LZX (`FSCTL_SET_EXTERNAL_BACKING`), recursive, with the saved bytes measured after.
- **Hard-link dedup:** replace confirmed duplicates on one volume with hard links (preview, undo by copying back).
- **Remove empty folders** (preview), **set folder dates to the newest change below**.
- **System cleanups** (Windows, each previewed with its size, each needing elevation through a one-shot helper): disable hibernation (`powercfg /h off`, shows `hiberfil.sys` size), optimize VHD/VHDX (`Optimize-VHD` or DISM), DISM component store analyze and cleanup; launchers for Disk Cleanup, Programs and Features / Installed apps, Storage settings (macOS: Storage settings; Linux: none).
- **User-defined cleanups,** unlimited: title, command line with placeholders (`%p` full path, `%n` name, `%s` path without trailing separator, `%d` folder for files or the folder itself, `%e` extension, `%%`), works for files / folders / drives, recurse into subfolders, ask before running (shows the expanded command), refresh after, show console window, wait for exit; stored per profile; reachable from the palette.
- **Recover deleted files** (WinDirStat 2.9): NTFS (unused MFT records with intact `$DATA` runs), exFAT (directory entries with the in-use bit clear), FAT12/16/32 (0xE5 entries, first character guessed), Recycle Bin items with their original name and path; read-only volume handle, admin, recover only to another volume; a list with confidence (clusters still free or not); fuzz targets for each parser.
- Context-menu registration for Explorer (per user) and a toggle in Settings to remove it.

**Tests:** each cleanup inside a VHDX or temp folder, placeholders expansion (paths with spaces, quotes, unicode), recovery of files deleted in fixture images for each file system, refusal to recover onto the source volume.

**Commits:** `feat(vfs): NTFS and WOF compression`, `feat(app): hard-link dedup, empty folders, folder dates`, `feat(app): system cleanups`, `feat(app): user-defined cleanups`, `feat(vfs): deleted file recovery`, `docs: cleanups and recovery`

### Task 86: export, reports and the command line (worktree `task86`)

**Design points:**
- Export the tree, file types, largest files, duplicates and permissions as CSV (UTF-8, BOM option) or JSON; copy the shown list to the clipboard as text; **Report…** writes an HTML summary (top folders, file types, largest files, treemap image) and offers to attach it to a new mail in the default mail client (WinDirStat 1.x's email report).
- `keel du` grows WinDirStat's unattended options: scan options as flags (filters, follow links, hard links, size on disk), `--save-to <file.csv|.json>`, `--save-dupes-to`, `--save-perms-to`, `--load-from`, `--top N`, exit after writing; API ops `du.scan`, `du.result`, `du.export` and MCP tools.
- Options gathered in Settings → Disk usage (every option of Tasks 81 to 85), portable INI covered by Phase 16's portable mode, translations by Phase 16's localization.

**Commits:** `feat(app): disk usage export and report`, `feat(cli): keel du report options`, `feat(api): disk usage ops`, `docs: export and command line`
