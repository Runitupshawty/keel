# Keel Phase 7 Implementation Plan: media + protection

> **For agentic workers:** same rules as earlier plan headers. Read spec 2.10 (media, protection), the Phase 6 plan (keel-core interfaces: Library, Source, record schema, Jobs, op_log), and the keel-preview APIs. Everything here builds on `keel-core` (Phase 6) and must keep working when the library is disabled (media sidecars then live only in the preview cache; protection views are hidden).

**Goal:** photos and videos feel instant (persistent thumbnail/proxy sidecars, a 60 fps grid over 100k items, video thumbstrips + scrubbing, EXIF/XMP, HEIC), and James can see how safe his data is (redundancy by failure domain, backup state, integrity drift, drive inventory, last-copy warnings) with cloud sources indexed like local ones.

**Global constraints:** sidecar generation is a durable keel-core job at idle priority (one thread, pauses on activity/battery); the UI thread never decodes; sidecars are content-addressed (`<cache>/sidecars/<cas-id or path-hash>/thumb-256.webp`, `thumb-1024.webp`, `strip.webp`, `meta.json`) so a moved file keeps them; the sidecar store has a byte budget (default 10 GiB, LRU); every protection number is explainable in the UI (hover shows how it was computed); no new C dependencies unless pure-Rust is impossible (libheif is optional, feature-gated, off by default).

**Review focus:** (1) a 129k-photo folder scrolls at 60 fps with thumbnails arriving without stutter (decode off the hot path, texture uploads budgeted per frame); (2) a corrupt/huge media file never blocks sidecar generation for others; (3) protection counts never overstate redundancy (two copies on the same physical disk or same cloud account are one failure domain); (4) EXIF orientation respected everywhere; (5) sidecar budget eviction never deletes a sidecar in use.

### Task 31: `keel-core` media sidecars + metadata (worktree `task31`)

**Deps:** `image` (+ `webp` encode via `image` or `webp` crate), `kamadak-exif`, `xmp-toolkit`? (prefer parsing XMP packets with `quick-xml`), `libheif-rs` behind feature `heic` (off), ffmpeg CLI (existing keel-preview helper) for video.

**Interfaces (Produces):**
```rust
pub struct Sidecars { root: PathBuf, budget: u64 }
impl Sidecars { pub fn open(root: &Path, budget: u64) -> Result<Self>; pub fn get(&self, key: &SidecarKey, kind: SidecarKind) -> Option<PathBuf>; pub fn ensure(&self, key: &SidecarKey, kind: SidecarKind, source: &Path) -> Result<PathBuf> /* generates if missing; blocking, call from a job */; pub fn evict_to_budget(&self, pinned: &dyn Fn(&SidecarKey) -> bool); pub fn stats(&self) -> SidecarStats; }
#[derive(Clone, Hash, Eq, PartialEq)] pub struct SidecarKey { pub cas_id: Option<[u8; 32]>, pub path_hash: [u8; 32], pub mtime: i64, pub size: u64 }
#[derive(Clone, Copy)] pub enum SidecarKind { Thumb256, Thumb1024, Strip /* 20 frames x 160 px for video */, Meta }
#[derive(Serialize, Deserialize, Default)] pub struct MediaMeta { pub width: u32, pub height: u32, pub orientation: u8, pub taken_at: Option<i64>, pub camera: Option<String>, pub lens: Option<String>, pub gps: Option<(f64, f64)>, pub duration_ms: Option<u64>, pub codec: Option<String>, pub rating: Option<u8>, pub keywords: Vec<String> }
pub fn read_meta(path: &Path) -> Result<MediaMeta>;   // EXIF via kamadak-exif, XMP packet scan, ffprobe for video
pub struct SidecarJob; // keel-core Job: walks records of kind image/video in a source, ensures Thumb256 + Meta (Thumb1024/Strip on demand), checkpoints every 500, idle-priority
```
Record schema addition: `media(record, width, height, orientation, taken_at, duration_ms, camera, gps_lat, gps_lon)` + FTS fields for camera/keywords.

**Steps:** (1) Sidecars store + key + eviction with pin callback, tests incl. budget eviction; (2) thumbnails via `image` with EXIF orientation applied, webp encode, size caps (skip > 200 MP), corrupt files recorded as error in `meta.json`; (3) video thumbstrip via ffmpeg (`-vf fps=20/duration,scale=160:-1,tile=20x1`) with the 10 s timeout helper from keel-preview; (4) `read_meta` tests on committed tiny fixtures (jpeg with EXIF + orientation 6, png, a 2 s mp4 generated at test time); (5) SidecarJob with checkpoint/restore test and idle pause (activity flag + battery check via `battery` crate behind feature); (6) HEIC behind `heic` feature (compile-checked only unless libheif present); commit `feat(core): media sidecars, metadata extraction, idle sidecar job`.

### Task 32: 60 fps media grid + viewer (worktree `task32`, keel-app)

- `ViewMode::Media`: square-tile grid (sizes S/M/L), virtualized rows, tiles show Thumb256 textures loaded from sidecars through a bounded uploader (≤ 8 texture uploads per frame, prefetch ±2 screens, LRU 4,000 textures); missing sidecars request generation (priority queue, visible first) via a worker and show a neutral placeholder (no spinner per tile); videos show the first strip frame and scrub across the strip on hover; EXIF orientation applied; date headers (group by taken_at day) optional.
- Viewer: Space / Enter opens a full-window viewer (Thumb1024 immediately, full decode in the background), arrows navigate, zoom/pan, video playback via the existing egui-video path with the strip as a scrubber, Esc closes; info panel (MediaMeta) toggle `I`.
- Perf test (`#[ignore]`): 129,000 synthetic sidecars; scrolling 10 screens keeps frame time < 16 ms (measure with egui's frame timing in a kittest harness; report numbers).
- Commit `feat(app): media grid and viewer`.

### Task 33: protection model + drive inventory (worktree `task33`)

- keel-core: `Volume { id (serial/GUID), label, kind (Fixed/Removable/Network/Cloud), failure_domain: String /* physical disk id, pool, cloud account */, state: Online/Offline/Archived/Lost/Retired, last_seen }`, `record_copies(cas_id) -> Vec<(record, volume)>`, `redundancy(cas_id) -> Redundancy { copies, domains }`, backup state = presence in a volume flagged `backup: true`, integrity = re-hash sample on a schedule and compare (drift → warning), capacity per volume; drive inventory editable (mark Archived/Lost/Retired; offline volumes keep their records).
- keel-app: Protection tab in Overview (per-volume table, totals, "N files have one copy only", "M files changed since last check"), per-record badge in details view (copies count on hover), delete/move previews show "last copy" warnings from keel-core's Plan, drive inventory editor.
- Cloud sources: `SourceKind::Cloud` indexes through the cloud provider listing (paged), counted as its own failure domain.
- Tests: redundancy never counts two copies in one domain twice; offline volume copies count with a flag; integrity drift detection on a modified fixture.
- Commit `feat(core,app): protection model, drive inventory, cloud sources`.
