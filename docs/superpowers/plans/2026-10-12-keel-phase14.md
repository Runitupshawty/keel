# Keel Phase 14 Implementation Plan: a Finder-style interface

> **For agentic workers:** same rules as earlier plan headers. Each task gets its own worktree, branched from the release Phase 14 starts on (0.22.0). Run `cargo fmt --all --check`, `cargo clippy --all-targets -- -D warnings` and the tests of the crates touched before every commit. Every user-visible change goes into the docs and the CHANGELOG in the same task, and the screenshots in `docs/screenshots` are made again at the end of the phase (CONTRIBUTING.md says how). Public repo: no hostnames, IPs, user names, personal names or personal paths in code, tests, fixtures, screenshots or commit messages.
>
> **Design tool.** The owner asked for the **impeccable** design skill (Apache-2.0, `github.com/pbakaus/impeccable`; installed as a Claude Code skill). Use it as the design reviewer of this phase: Task 64 starts with `/impeccable init` (writes `PRODUCT.md`) and `/impeccable document` (writes `DESIGN.md` from the current theme code), every UI task ends with `/impeccable critique` and `/impeccable polish` on screenshots of the change, and Task 69 runs `/impeccable audit`. Its detectors read HTML and CSS, so they run directly on the web client (`crates/keel-web`); for the egui window, feed it screenshots from the walkthrough harness (`screenshots.rs`) and apply its findings by hand. Its "Operate" mode is the one that fits a file manager.

**Why this phase comes first.** Phases 15 to 17 add some forty new surfaces (search toggles, filter sidebar, bookmarks, history, a treemap, an extension list, a sunburst, cleanups). Building the new look first means they are built once, in it, instead of restyled later. If the owner wants the features first, Phases 15 to 17 do not depend on this one and can run before it; only their screenshots then need making again.

**Goal:** Keel looks and behaves like the macOS Finder on every platform, as an optional **Finder** appearance that becomes the default: a unified toolbar in the title bar, a translucent sidebar with Favorites, Locations and Tags sections, a list view with disclosure triangles, an icon view, Column and Gallery views, a path bar, Finder tag colors, Quick Look on Space, Get Info, and Finder's spacing, type, selection and motion. The existing look stays as the **Classic** appearance for users who prefer it.

**Not copied:** Apple's artwork, the SF Pro and SF Symbols fonts and Apple's icons are not redistributable. Keel draws its own folder and file icons in the same spirit, uses Inter (OFL-1.1) as the interface font on Windows and Linux and the system font on macOS, and Lucide (ISC) or the existing icon set for toolbar glyphs. No Apple names or trademarks appear in the interface beyond the setting name "Finder-style" in docs.

**Live checks.** On the owner's Windows desktop and Mac, with generated fixtures in a temporary folder and `KEEL_CONFIG_DIR`, `KEEL_DATA_DIR` and `KEEL_NET_SECRET=memory` set as the first statement of every shell command, so the owner's settings, library and keyring are never touched. Each task compares a screenshot of Keel beside a screenshot of Finder showing the same fixture folder, taken on the owner's Mac.

**Review focus:**
1. Nothing a user could do before is lost or hidden: every action still has a menu, palette and keyboard path; the dual pane, terminal, tabs and jobs panel still work in the Finder appearance.
2. Accessibility holds: AccessKit names on every new control, contrast measured against WCAG AA in light and dark (the existing contrast tests extended), Reduce motion respected, keyboard focus visible on the translucent sidebar.
3. Custom window chrome behaves like a native window on each OS: drag, double-click to maximize, snap layouts on Windows 11 (hover on maximize), resize from every edge, the system menu, and correct behavior with two monitors at different scales.
4. Performance does not regress: the measured first frame, 100,000-file folder open and 129,000-tile media view numbers in `docs/performance.md` are measured again and stay within 10%.
5. Fonts and icons shipped are licensed for redistribution and listed in `THIRD_PARTY.md`.

### Task 64: design system and the Finder appearance tokens (worktree `task64`)

**Read:**
- `crates/keel-app/src/theme.rs`, `color_theme.rs` (+ tests), `fonts.rs`, `anim.rs`, `assets/themes/`, `docs/files.md` (Color themes), the contrast tests.
- Every place that hard-codes spacing, rounding or colors: `rg -n "Rounding|rect_filled|Color32::from_rgb|item_spacing|Margin::" crates/keel-app/src`.

**Design points:**
- Run `/impeccable init` and `/impeccable document` first; commit `PRODUCT.md` (Operate mode, audience: people leaving Explorer and Finder) and `DESIGN.md` at the repo root.
- **Tokens** in one module `design.rs`: spacing scale (4 px base: 2, 4, 6, 8, 12, 16, 20, 24), corner radii (selection 5, controls 6, panels 10, window 10 on macOS 11+ style), row heights (list 22 at default size, sidebar 24, toolbar 38 / 52 with labels), type scale (11, 12, 13 body, 15 titles; one family), the eight Finder tag colors (red, orange, yellow, green, blue, purple, gray, none) as named tokens, semantic colors (window background, sidebar material, content background, separator, selected-focused accent, selected-unfocused gray, alternating row, secondary label, tertiary label) for light and dark.
- **Appearance setting:** Settings → Appearance → **Style: Finder / Classic** (Finder default for new profiles; existing profiles keep Classic until switched, with a one-time banner offering it). Color themes keep working on top of either style: a theme overrides colors, the style sets shapes, spacing and chrome.
- **Accent color:** follows the OS accent on Windows (`UISettings`) and macOS (`NSColor.controlAccentColor`), else blue; overridable.
- **Fonts:** Inter variable (OFL) embedded for Windows and Linux; on macOS load the system font through `font-kit` or the existing font discovery; Hack stays for the terminal and code previews.
- Replace every hard-coded constant found above with tokens, so Classic is just another token set.

**Tests:** token sets for Finder light/dark and Classic light/dark pass the contrast tests (text 4.5:1, secondary 3:1, focus ring 3:1); the style setting round-trips through the profile; a snapshot test per style of a fixture window (the walkthrough harness).

**Docs:** `docs/files.md` (Appearance: styles, accent), `docs/features.md`, `THIRD_PARTY.md` (Inter), CHANGELOG.

**Commits:** `feat(app): design tokens`, `feat(app): Finder appearance tokens and style setting`, `docs: appearance styles`

### Task 65: window chrome, unified toolbar and sidebar (worktree `task65`)

**Read:** `app.rs` (top-level layout), `pane.rs` (nav bar, view buttons at 357-370), `sidebar.rs`, `sidebar_remotes.rs`, `library_ui.rs` (sidebar sections), `platform.rs`, eframe 0.31 `ViewportBuilder` (`with_decorations`, `with_transparent`, `with_titlebar_shown`, `with_fullsize_content_view`, `with_title_shown`).

**Design points:**
- **Title bar:** in Finder style the toolbar lives in the title bar. macOS: `fullsize_content_view` + hidden title, real traffic lights kept. Windows: client-side decorations (no system title bar) with Keel-drawn minimize/maximize/close on the right in Windows style (Finder-style window controls on Windows would confuse; follow the platform), hit-testing for drag, double-click, snap-layout hover (WM_NCHITTEST HTMAXBUTTON through a small `windows`-crate subclass) and Mica/Acrylic backdrop on Windows 11 via `DwmSetWindowAttribute` when available. Linux: server-side decorations unless the desktop is GNOME with CSD preference; never break tiling WMs.
- **Toolbar** (left to right, Finder order): sidebar toggle, back / forward, the folder title (current folder name, with a menu of parents on click), then right-aligned: view switcher as a segmented control (Icons, List, Columns, Gallery, plus Media and Sizes in an overflow), Group by menu, Share (Spacedrop and copy link), Tags menu, Action menu (the context menu of the folder), and a search field that expands on focus. Customize Toolbar dialog: drag items in or out, Icon only / Icon and text, restore default. Toolbar layout per profile.
- **Sidebar** sections with collapsible headers on hover (Finder's "Hide/Show"): **Favorites** (user-arranged: drag a folder in to pin, drag out or right-click to remove; seeds: Recents, Applications/Programs, Desktop, Documents, Downloads, Home), **Locations** (this PC's drives with eject buttons for removable ones, network shares, SFTP/FTP hosts, cloud accounts, devices, WSL), **Library** (sources, saved views, which Phase 16 makes "Smart Folders"), **Tags** (the library's tags with their color dots; "All Tags…"). Translucent material on macOS (`NSVisualEffectView` sidebar material behind the egui panel with a transparent clear color) and Mica on Windows 11; solid elsewhere.
- Rounded-pill selection in the sidebar, icons tinted with the accent, counts hidden.
- Closes parity gap "Places, pinned folders, user-arranged sidebar" (Spacedrive row) too.

**Tests:** sidebar pin/unpin/reorder persists; toolbar customization persists; hit-test regions (unit tests on the layout function: title area drags, buttons don't); keyboard: Ctrl/Cmd+Alt+S toggles the sidebar, Cmd/Ctrl+[ and ] go back/forward.

**Docs:** `docs/files.md` (Window and toolbar, Sidebar), getting-started, CHANGELOG.

**Commits:** `feat(app): unified title bar toolbar`, `feat(app): Finder sidebar with Favorites, Locations, Library and Tags`, `docs: toolbar and sidebar`

### Task 66: the four Finder views (worktree `task66`)

**Read:** `view_details.rs`, `view_grid.rs`, `view_columns.rs`, `view_media.rs`, `tab.rs` (sort keys, listing), `preview_panel.rs`, `inspector.rs`.

**Design points:**
- **List view:** disclosure triangles expand folders inline (Right/Left arrows, Alt+click expands all below), children indented; columns chosen by right-clicking the header (Name, Date Modified, Date Created, Date Last Opened, Date Added, Size, Kind, Version, Comments, Tags), alternating row backgrounds, relative dates ("Today at 14:05", "Yesterday"), folder sizes as in "Calculate all sizes" (reuses folder totals), Kind as human words ("PDF document"), View Options panel (Cmd/Ctrl+J): icon size, text size, columns, "Use relative dates", "Calculate all sizes", "Show icon preview", "Always open in list view", "Use as defaults".
- **Icon view:** large icons with thumbnails, labels under icons with two-line wrapping and middle truncation, free arrangement or Snap to grid / Sort by, icon size slider (16 to 512), grid spacing slider, label position bottom/right, "Clean Up" and "Clean Up By", background color or picture per folder (kept with folder styles).
- **Column view:** existing Miller columns restyled: a preview column at the end with a large thumbnail and info (name, kind, size, dates, tags, "More…"), resizable columns, "Right Size All Columns Equally".
- **Gallery view:** a big preview of the selected file with a thumbnail strip under it, the metadata sidebar (Preview pane) on the right with Quick Actions (Rotate, Markup, Create PDF, Convert Image, Trim video; the ones Keel has, others hidden), arrow keys move through items. Folders show a big folder icon. Replaces nothing: Media view stays as the photo grid.
- **Group by** (Kind, Application, Date Last Opened, Date Added, Date Modified, Date Created, Size, Tags, None) in Icon and List views with sticky group headers.
- **Sort by** independent of Group by; View → Show Path Bar, Show Status Bar, Show Tab Bar, Show Preview.
- Per-folder view settings remembered (Finder's "Always open in…"), stored in the profile by path.
- Middle truncation of long names everywhere (`My Long Fi…me.pdf`).

**Tests:** expand/collapse state with keyboard, sort + group combinations, per-folder view memory, middle truncation (unicode-aware), a 100,000-file folder in List with all groups collapsed stays at the measured speed.

**Docs:** `docs/files.md` (Views), CHANGELOG.

**Commits:** `feat(app): list view with disclosure triangles and view options`, `feat(app): icon view arrangement`, `feat(app): gallery view`, `feat(app): group by`, `docs: Finder views`

### Task 67: Quick Look, Get Info, path bar, status bar, tags (worktree `task67`)

**Design points:**
- **Quick Look:** Space opens a floating preview window over the file list (the preview renderers Keel has: images, video and audio playback, PDF, Office, text, code, archives), arrow keys move the selection and the preview follows, Space or Esc closes, a full-screen button, "Open with…" button, an index sheet (grid) for several selected files. Replaces the current Space behavior; the docked preview panel (F3) stays.
- **Get Info** (Cmd/Ctrl+I in Finder style; the Inspector keeps Ctrl+Shift+I): a Finder-style info window per file with collapsible sections General (kind, size, size on disk once Phase 17 has it, where, created, modified, tags, locked), More Info (media metadata), Name & Extension, Comments, Open with, Preview, Sharing & Permissions (Windows ACL summary, Unix owner/mode); several Get Info windows can be open; Option/Alt+Cmd/Ctrl+I opens one Inspector that follows the selection. The existing Properties dialog becomes this window.
- **Path bar** at the bottom: icon + name crumbs, double-click to open, drag files onto a crumb to move, Option/Alt-drag to copy; right-click shows "Copy as Pathname".
- **Status bar** under the path bar: "12 items, 431.2 GB available", with an icon-size slider in icon view.
- **Finder tags:** library tags get one of the eight Finder colors (existing color stored as is; the picker offers the eight), shown as colored dots after file names in every view, in the sidebar Tags section and the context menu's tag row (click a dot to toggle), with Tags… for more. Reading and writing native macOS tags (`com.apple.metadata:_kMDItemUserTags` xattr) on local files on macOS, so tags set in Finder show in Keel and back; elsewhere tags stay in the library.
- **Spring-loaded folders:** hovering a drag over a folder for 0.6 s opens it (setting, on by default); Space while hovering opens at once.
- **New Folder with Selection** (Ctrl+Cmd+N on macOS, Ctrl+Alt+N elsewhere), **Duplicate** (Cmd/Ctrl+D), **Make Alias** (shortcut/symlink), **Show Enclosing Folder** (Cmd/Ctrl+R in search results), **Go to Folder** (Cmd/Ctrl+Shift+G with path completion), **Get Info**, **Compress** naming like Finder ("Archive.zip").

**Tests:** Quick Look navigation, Get Info for a file, a folder, a drive and several items; xattr tag round-trip on macOS (CI macOS job, temp dir); spring-loading timer; path bar drop moves and Alt-drop copies.

**Docs:** `docs/files.md` (Quick Look, Get Info, path bar, tags), CHANGELOG.

**Commits:** `feat(app): Quick Look`, `feat(app): Get Info window`, `feat(app): path bar and status bar`, `feat(app): Finder tag colors and macOS tag sync`, `docs: Quick Look, Get Info, tags`

### Task 68: icons, motion and the web client (worktree `task68`)

**Design points:**
- **Icon set:** a new built-in icon theme "Keel Finder": folders as rounded blue folders with a darker tab, special folders (Desktop, Documents, Downloads, Pictures, Music, Movies/Videos, Home, Applications/Programs, Trash) with an embossed glyph, document icons with a folded corner and the extension label, drawn as SVG in-house (no Apple artwork), rendered at all sizes 16 to 512 and cached as textures. Existing VS Code icon themes keep working.
- **Motion:** 150 to 250 ms ease-out for disclosure, sidebar collapse, Quick Look zoom from the item's position, view switches cross-fade; all off under Reduce motion.
- **Web client:** `crates/keel-web` adopts the same tokens (sidebar, toolbar, list with disclosure triangles, tag dots) generated from `design.rs` into CSS custom properties at build time; run `/impeccable audit` and `/impeccable polish` on it directly (its detectors work on the web client's DOM through the Playwright run).

**Tests:** icon rendering snapshot at 16/32/128 px, motion durations zero under Reduce motion, web e2e screenshots updated.

**Commits:** `feat(app): Keel Finder icon theme`, `feat(app): Finder motion`, `feat(web): Finder style tokens`, `docs: icons and motion`
