# Keel Phase 5 Implementation Plan: polish

> **For agentic workers:** same rules as the Phase 2-4 plan headers. Read spec 2.5, 2.6, 2.9, the Phase 1 Amendments, and `docs/superpowers/plans/2026-10-09-polish-backlog.md`.

**Goal:** the things that make Keel feel finished: the review backlog, profiles, an icon-theme manager, Miller columns, a drop zone, drag-out to the OS, a global hotkey with single-instance, and the own NTFS indexer so Windows search works without Everything.

---

### Task 21: polish backlog (worktree `task21`)
Work through every bullet in `2026-10-09-polish-backlog.md` (keel-app, keel-vfs, keel-search, keel-preview sections), one commit per section, a test for every bullet that names a scenario. Items already fixed by later tasks are ticked off in the backlog file (edit it in this task). Commit `fix: polish backlog`.

### Task 22: profiles + icon-theme manager (worktree `task22`)
- Profiles: `<config>/profiles/<name>/config.toml`; Settings → Profiles: list, New (copy current), Rename, Delete, Switch; palette "Switch profile: <name>"; the session file is per profile; command line `keel --profile <name>`.
- Icon themes: Settings → Icons: list installed themes under `<config>/icons/<theme>/` plus the built-in; "Install from VS Code Marketplace…" takes an extension id (e.g. `PKief.material-icon-theme`, `vscode-icons-team.vscode-icons`), downloads the `.vsix` from `https://marketplace.visualstudio.com/_apis/public/gallery/publishers/<pub>/vsextensions/<name>/latest/vspackage` on a worker with progress, unzips it, reads `package.json` → `contributes.iconThemes[0].path`, parses the icon theme JSON (`iconDefinitions`, `fileExtensions`, `fileNames`, `folderNames`, `languageIds`, `light`/`highContrast` variants) and maps it onto `icons::icon_for` (extension → svg/png path, folder/folder-open, default file). Themes switch at runtime without restart. Tests: parser on a committed minimal theme JSON; mapping precedence (fileNames > fileExtensions > languageIds > default). Commit `feat(app): profiles; VS Code icon theme manager`.

### Task 23: Miller columns + drop zone + animations (worktree `task23`)
- `ViewMode::Columns`: cascading columns (Finder style) inside a pane: each column is a folder listing; selecting a folder opens the next column; the last column shows the preview for a file; horizontal scroll; keyboard Left/Right move between columns; column widths draggable and remembered.
- Drop zone: a collapsible strip above the status bar (toggle Ctrl+Shift+Z) that holds a stash of paths across navigation; drag rows onto it or press Ctrl+Shift+S to stash the selection; from the strip: Paste here (copy), Move here, Clear, remove one; persisted in the session.
- Animations: 120 ms eased transitions for pane split, panel collapse, selection highlight, toast slide; respect a "reduce motion" setting; never animate list content.
- Tests: columns model (open folder in column n closes columns > n), stash add/remove/persist. Commit `feat(app): Miller columns, drop zone, animations`.

### Task 24: drag-out, global hotkey, single instance (worktree `task24`)
- Drag-out to the OS (Windows first): start an OLE drag with an `IDataObject` carrying `CF_HDROP` when a row drag leaves the Keel window; implemented in a cfg(windows) module in keel-vfs (`drag_out::start(paths, allow_move) -> DropEffect`) run on a dedicated STA thread so it never blocks the UI; macOS via `NSDraggingSession` with file URLs (objc2) best effort; Linux: XDnD / Wayland data-source via `arboard`-style helpers if feasible, else documented as unsupported.
- Global hotkey (default Ctrl+Shift+Alt+K as shipped, since Ctrl+Alt is AltGr on many layouts; configurable) that focuses or launches Keel, via `global-hotkey` crate; single instance: a local socket / named pipe (`interprocess` crate) so a second `keel <path>` opens a tab in the running instance.
- `keel` CLI flags: `keel <folder>`, `keel --new-window`, `keel --profile <name>`, `keel --search "<query>"`.
- Tests: single-instance handshake over the local socket; CLI parsing. Commit `feat(app): drag-out, global hotkey, single instance, CLI flags`.

### Task 25: own NTFS indexer (worktree `task25`, Windows)
- `keel-search` `NtfsSearcher`: enumerate the MFT via `FSCTL_ENUM_USN_DATA` per fixed NTFS volume (requires elevation; if not elevated, fall back to a `ReadDirectoryChangesW`-fed `walkdir` index of user folders only, with a toast explaining the difference), keep it current with the USN journal (`FSCTL_READ_USN_JOURNAL`), store the index in `<cache>/index/<volume>.db` (sled or rusqlite), rebuild when the journal id changes; query = substring/glob/regex over names with the same `Query` type; `folder_index` served from it; `default_searcher()` prefers Everything when running, else Ntfs, else walk.
- Elevation: an "Index all drives (needs administrator)" button relaunches `keel --index-service` elevated for the enumeration only; the index files are owned by the user afterwards.
- Perf: 2 million entries indexed in < 60 s on the desktop PC; query < 20 ms. Tests against a VHD or a temp NTFS volume are optional; unit-test the USN record parser with captured bytes.
- Commit `feat(search): own NTFS/USN indexer with elevation-free fallback`.
