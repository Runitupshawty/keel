# Keel Phase 3 Implementation Plan: remotes over SFTP

> **For agentic workers:** same rules as Phase 2's plan header (worktree per task, TDD, fmt + clippy on three targets + tests before every commit, no `windows` crate in keel-app, no IO on the UI thread, cfg-gated OS code). Read spec 2.1 (sftp provider), 2.6 (profiles), 2.7 (error handling), 2.9, and the Phase 1 plan Global Constraints + Amendments first.

**Goal:** any SSH host appears in the sidebar as a folder tree: browse, preview, open-with (materialised), copy/move between local and remote and remote↔remote (via local staging), rename/mkdir/delete on the remote, all with progress and reconnect. James's hosts (Mac mini with an iCloud Drive bookmark, Mac Studio, XPS laptop, the file server) are configured in his profile, never in the repo.

**Security rules:** keys from `~/.ssh` or the SSH agent (Pageant / OpenSSH agent on Windows, `SSH_AUTH_SOCK` elsewhere); passwords only via the OS keychain (`keyring` crate), never written to config; host keys verified against `~/.ssh/known_hosts` with a first-connect "trust this fingerprint?" dialog (TOFU) and a mismatch hard-fail; no credentials in logs or toasts.

**Review focus:** (1) a dropped connection mid-listing or mid-copy must not lose data or leave a half-written remote file (upload to `.keel-partial` then rename); (2) a hung host never blocks the UI (every call has a timeout; listing shows a spinner then an error); (3) known_hosts mismatch is a hard error with a clear message; (4) paths with spaces, unicode, and symlinks on the remote; (5) 50,000-entry remote directory lists in one round-trip batch and stays scrollable.

### Task 15: `keel-vfs` SFTP provider (worktree `task15`)

**Files:** `crates/keel-vfs/src/sftp/{mod.rs, conn.rs, hostkeys.rs, auth.rs}`, modify `router.rs` (register per-host providers at runtime: `Router::register_remote(host: RemoteHost)`), tests `crates/keel-vfs/tests/sftp.rs` (run only with `KEEL_SFTP_TEST=user@host[:port]` and `KEEL_SFTP_TEST_DIR=/tmp/keel-test`; otherwise skipped with a printed reason).

**Deps (workspace):** `russh = "0.50"`, `russh-sftp = "2"`, `russh-keys` (if separate), `tokio = { version = "1", features = ["rt-multi-thread", "net", "io-util", "time", "macros"] }` (one shared runtime inside keel-vfs; the Provider API stays synchronous and blocks the calling worker thread with timeouts), `keyring = "3"`, `ssh-key` for parsing known_hosts, `dirs`/`directories`.

**Interfaces (Produces):**
```rust
#[derive(Clone, Debug, PartialEq, serde::Serialize, serde::Deserialize)]
pub struct RemoteHost { pub id: String /* stable slug, used as VPath authority */, pub label: String, pub host: String, pub port: u16, pub user: String,
                        pub auth: RemoteAuth, pub home: Option<String> /* initial dir */, pub bookmarks: Vec<(String /*label*/, String /*remote path*/)> }
#[derive(Clone, Debug, PartialEq, serde::Serialize, serde::Deserialize)]
pub enum RemoteAuth { Agent, KeyFile { path: PathBuf, passphrase_in_keyring: bool }, PasswordInKeyring }
pub struct SftpProvider { host: RemoteHost, conn: Arc<ConnPool> }
impl SftpProvider { pub fn new(host: RemoteHost, events: Sender<RemoteEvent>) -> Self; pub fn status(&self) -> ConnStatus; }
#[derive(Clone, Copy, Debug, PartialEq)] pub enum ConnStatus { Disconnected, Connecting, Connected, Failed }
#[derive(Clone, Debug)] pub enum RemoteEvent { Status { host_id: String, status: ConnStatus, detail: String }, HostKeyPrompt { host_id: String, fingerprint: String, reply: Sender<bool> } }
impl Provider for SftpProvider { /* scheme "sftp"; list/stat/read/write/create_new/mkdir/rename/remove (remote delete = real delete after the app's confirm; Caps { delete: true, .. }); local_copy streams to <cache>/remote/<host_id>/<hash>/<name> with mtime+size check and a progress callback variant `local_copy_with_progress` */ }
// Connection pool: one SSH session per host, lazily opened, reopened on error with backoff 1,2,4,8 s (max 30 s), every operation has a 20 s timeout (configurable), `ConnPool::disconnect()`.
pub fn known_hosts_check(host: &str, port: u16, key: &PublicKey) -> HostKeyVerdict; // Known, Unknown(fingerprint), Mismatch
pub fn add_known_host(host: &str, port: u16, key: &PublicKey) -> Result<()>;
// ops.rs additions: transfers between any two providers
pub fn transfer(src: &[VPath], dst_dir: &VPath, mv: bool, on_conflict: Conflict, progress: &dyn Fn(Progress), cancel: &AtomicBool, router: &Router) -> Result<()>;
// local→local delegates to copy_local/move_local; otherwise streams read()→write() through a 1 MiB buffer, uploads to `<name>.keel-partial` then renames, deletes source only after a verified size match when mv.
```

**Steps:** (1) `RemoteHost` serde round-trip + VPath `sftp://<id>/path` parsing; (2) tokio runtime + `ConnPool` with timeout + backoff, unit-tested against a local in-process fake (the `russh` server API) or against `KEEL_SFTP_TEST`; (3) auth: agent (Windows named pipe `\\.\pipe\openssh-ssh-agent`, Pageant optional later), key file (ed25519/rsa/ecdsa, optional passphrase from keyring), password from keyring; (4) known_hosts verdicts + TOFU add (test with a temp HOME); (5) `list` via `readdir` in batches (test 50k entries if the test host allows); (6) read/write/create_new/mkdir/rename/remove with `.keel-partial` uploads; (7) `local_copy_with_progress` + cache keyed by (host, path, mtime, size); (8) `transfer` with conflict flow + cancel + partial cleanup tests (local↔remote both ways, remote↔remote); (9) Linux/macOS `cargo check`; commit `feat(vfs): SFTP provider with agent/key/password auth, known_hosts, streaming transfers`.

### Task 16: app integration of remotes (worktree `task16`, after 15 and Phase 2 merge)

- Settings → Remotes: list, Add/Edit/Remove dialog (label, host, port, user, auth method, key file picker via `rfd`, "store password in keychain" field that writes to `keyring` and never to config, initial dir, bookmarks). Stored in `config.toml` under `[[remotes]]`.
- Sidebar "Remotes": each host with status dot (grey/yellow/green/red), click opens its initial dir in the active pane; bookmarks nested; right-click: Connect, Disconnect, Edit, Open terminal here (ssh in the terminal pane: `ssh user@host`), Copy address.
- Host key prompt modal (fingerprint, Trust / Cancel); status toasts; "reconnecting…" banner in the tab; the tab is never lost.
- Jobs use `ops::transfer`; drag/paste between a local and a remote pane works; remote delete asks "Delete N items on <host>? This cannot be undone." (no trash remotely).
- Preview/open-with on remote files via `local_copy_with_progress` with a progress toast for large files; thumbnails off for remotes by default (setting).
- Session restore reconnects lazily (tab shows connecting state).
- Everything/Spotlight search stays local; a remote tab's Ctrl+F searches names in the current remote folder recursively (bounded to 20,000 entries) via the provider.
- Tests: remotes config round-trip; sidebar model from config; host-key prompt flow with a fake event; transfer job with the local provider on both sides (acts as a stand-in).
- Commit `feat(app): remotes in sidebar and settings, host key prompt, local<->remote transfers`.
