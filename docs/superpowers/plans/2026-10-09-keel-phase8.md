# Keel Phase 8 Implementation Plan: devices, remote sources, Spacedrop, daemon + API

> **For agentic workers:** same rules as earlier plan headers. Read spec 2.10 (Network, API and automation, Clients), the Phase 6/7 plans (keel-core Library/Source/Jobs), the Phase 3 plan (security rules for credentials), and keel-vfs provider patterns (sftp, cloud).

**Goal:** James's machines see each other: pair devices with a code, browse and operate another device's sources as `node://<device>/...`, send files with Spacedrop, share a subtree with a scoped revocable grant; and everything Keel does is callable from a CLI, JSON-RPC and an MCP server through a headless `keel-daemon`.

**Transport:** `iroh` (QUIC, end-to-end encrypted, direct with relay fallback, NAT traversal). Device identity = iroh node id (ed25519) stored in the OS keychain. Pairing = out-of-band short code (6 words / QR) that exchanges node ids + a per-pair secret; everything after is mutually authenticated. No account, no central server beyond iroh's public relays (self-hostable later; document how to point at the file server's relay).

**Security rules:** a paired device gets nothing until a grant exists; grants are per source/subtree with read or read-write, visible in both UIs, revocable instantly (the host refuses the next request); all metadata/content transfer is logged in op_log on both sides; the daemon's local socket is per-user (reuse the Phase 5 single-instance pipe security helpers); JSON-RPC over TCP/WebSocket is off by default and, when on, token-authenticated and loopback-only unless explicitly bound; the MCP server exposes only registered operations and always runs `validate → preview` before anything mutating, returning the preview for confirmation.

**Review focus:** (1) a revoked grant cannot be used (replay, in-flight transfer, cached session); (2) Spacedrop resumes after a network drop and never leaves partial files visible; (3) relay-only connectivity (both behind symmetric NAT) works; (4) no node secret ever leaves the keychain; (5) the daemon survives the UI closing and the UI reattaches; (6) MCP calls cannot bypass preview.

### Task 35: `keel-net` pairing + transport (worktree `task35`)
- Crate `keel-net`: `Node::open(keychain)` (creates/loads the iroh secret key), `Node::pair_code() -> PairCode` + `Node::pair_with(code)` (short code exchange over iroh's blob/ticket mechanism or a one-shot QUIC handshake), `Peers` table (id, label, last_seen, LAN/Relay/Offline, storage summary), connection status events, a tiny request/response protocol (`Request::{Ping, ListSources, List{source,path}, Stat, Read{range}, Write, Mkdir, Rename, Remove, Grants}` over a length-prefixed CBOR stream), per-peer grant checks on every request.
- Tests: two in-process nodes pair and ping over loopback; a revoked grant fails the next request; relay fallback (force relay via config) ping.
- Commit `feat(net): iroh node, pairing, peers, request protocol, grants`.

### Task 36: remote sources + Spacedrop (worktree `task36`)
- keel-vfs `NodeProvider` for `node://<peer>/<source>/<path>` (read + write per grant) using keel-net; keel-core `SourceKind::Device` indexing a peer's source through metadata projections (cached, generation per sync); Spacedrop: `send(peer, paths)` with resumable chunked transfer (BLAKE3 verification, `.keel-partial` naming, progress, cancel), receive-side accept prompt + inbox folder; shares UI: grant a source/subtree to a peer (read / read-write), list + revoke.
- App: sidebar "Devices" (status dots, storage), pair dialog (show code / enter code / QR via `qrcode` crate rendered to a texture), Spacedrop from the context menu + drop target in the sidebar, inbox toast.
- Tests: transfer resume after a simulated drop; receive refuses when no grant; projection cache invalidation.
- Commit `feat(net,vfs,app): remote sources, Spacedrop, shares`.

### Task 37: `keel-daemon` + CLI + JSON-RPC + MCP (worktree `task37`)
- `keel-api`: compile-time registered operations (`inventory` or a macro) with typed JSON schemas: list/stat/search/tags/jobs/plan(validate→preview)/execute(plan id)/sources/devices/spacedrop; `keel-daemon` binary hosting keel-core + keel-net, local socket (per-user) + optional WebSocket with token; the egui app connects to the daemon when running (and spawns it otherwise; falls back to in-process); CLI `keel` subcommands (`keel search`, `keel tag add`, `keel plan copy … | keel execute <id>`, `keel devices`, `keel drop <peer> <paths>`), output JSON with `--json`; MCP server (`keel mcp`) over stdio exposing the same operations as tools with preview-first semantics.
- Tests: schema generation round-trip; a CLI search against a fixture library; MCP tool list + a preview call; daemon reattach.
- Commit `feat(daemon,api,cli): headless daemon, JSON-RPC, CLI subcommands, MCP server`.
