# Keel Phase 12 Implementation Plan: small wins (drag-out everywhere, folder styles, filter chips, tag assign mode, the inspector, folder operations, `keel op`)

> **For agentic workers:** same rules as earlier plan headers. Read [docs/parity.md](../../parity.md) first: it ranks these gaps (#15, #17, #18, #19, #21, #25 and #26). Each task gets its own worktree, branched from the release Phase 12 starts on (0.20.0). Run `cargo fmt --all --check`, `cargo clippy --all-targets -- -D warnings` and the tests of the crates touched before every commit. Any new parser of outside bytes gets a fuzz target (see [docs/fuzzing.md](../../fuzzing.md)). Every user-visible change goes into the docs and the CHANGELOG in the same task. Public repo: no hostnames, IPs, user names, personal names or personal paths in code, tests, fixtures, screenshots or commit messages.

**Goal:** Seven small gaps that each remove a reason to leave Keel: dragging files out of Keel on macOS and Linux (the README roadmap's last platform item), an icon or color per folder, filter chips so friends can search the library without the query syntax, a tag assign mode with number keys, an inspector panel that puts copies, provenance and history in one place, the folder operations Spacedrive lists (merge, flatten, organize, attributes, links), and `keel op` plus an agent skill so an agent can drive any operation.

**Not in this phase:** text inside documents (#11) is Phase 13. Interface translations (#20), dated freezes (#22), index replication (#23) and extensions (#24) stay ranked.

**Live checks.** Wherever a brief says "live", run it on the owner's own Windows desktop, and on the owner's Mac or Linux machine where noted, with generated fixtures in a temporary folder and `KEEL_CONFIG_DIR`, `KEEL_DATA_DIR` and `KEEL_NET_SECRET=memory` set as the first statement of every shell command, so the owner's settings, library and keyring are never touched.

**Review focus:**
1. Drag-out never moves or deletes a file on its own: a target's "move" result is only acted on after Keel confirms the source is gone, exactly as the Windows path does.
2. Folder styles, tag assignment, filter chips and the inspector read the library and never change a file.
3. Folder operations go through plans: a preview that lists every move, the same conflict rules, cancel, undo where the kind allows, and a refusal (not a half result) when the preview no longer matches the disk.
4. `keel op` cannot execute anything that the API would preview first: the two-step protocol stays, and the agent skill documents it.
5. Every new UI surface has a name for accessibility and a keyboard path.

### Task 55: drag-out on macOS and Linux (worktree `task55`)

**Goal:** Dragging files from Keel into another program works on macOS and Linux as it does on Windows (OLE in `crates/keel-vfs/src/drag_out/win.rs`). Parity gap #15; the README roadmap item "drag-out on macOS and Linux".

**Read:**
- `crates/keel-vfs/src/drag_out/mod.rs` (the interface: `start(paths, allow_move, done)` → `DropEffect`) and `win.rs` (how the UI thread, the OLE loop and the `done` callback fit; what "move" means for Keel: it only refreshes).
- `crates/keel-app/src/dragout.rs` (where a drag starts from the file list, the threshold, the refresh after a move).
- How eframe exposes the native window: `raw-window-handle` through `eframe::Frame` (`window_handle()`), the `objc2`/`objc2-app-kit` crates already in the tree for the macOS Trash, and `x11rb` or `winit`'s X11 types if already present (check `Cargo.lock` before adding anything).
- `docs/files.md` (drag and drop), `docs/parity.md` row 15.

**Design points:**
- **macOS:** AppKit needs the drag to start from the NSView that received the mouse event, inside that event. From the UI thread, when egui reports the drag threshold crossed with the primary button held: take the window's `NSView` from the raw window handle, build one `NSPasteboardItem` per file (`public.file-url`), one `NSDraggingItem` each with the file icon from `NSWorkspace` as the image, and call `beginDraggingSession:event:source:` with `NSApp.currentEvent`. The source object (an `objc2` class defined in `drag_out/mac.rs`) answers `draggingSession:sourceOperationMaskForDraggingContext:` with Copy, plus Move when `allow_move`, and `draggingSession:endedAtPoint:operation:` calls `done` with the effect. Keel's own window as the target stays Keel's existing in-app drop.
- **Linux:** X11 through XDND (version 5) on the window from the raw handle: claim `XdndSelection`, offer `text/uri-list` (and `text/x-moz-url` is not needed), track the pointer with a grab, send `XdndEnter`/`XdndPosition`/`XdndDrop`/`XdndLeave`, answer `SelectionRequest` with the URI list, read `XdndFinished` for the action. Run the XDND loop on a thread with its own X connection and the window id; the UI thread keeps drawing. Wayland has no drag-out without a serial from the toolkit: report "dragging files to other apps needs X11 (XWayland) on this desktop" at once, as the stub does today, and document it.
- **Move semantics (review focus 1):** when the target reports Move, Keel checks that each source is gone (or still there: then nothing happened) and refreshes; it never deletes.
- **Keep the interface:** `drag_out::start` keeps its signature; `cfg` selects `win.rs`, `mac.rs`, `x11.rs` and the stub.

**Tests:**
- Unit tests of the URI list encoding (spaces, non-ASCII, `#`, `%`, a path with a newline refused) and of the pasteboard/XDND message builders where they are pure.
- `#[ignore]` live tests gated on an env var that drag into a scratch window are not practical: the live check is by hand.
- **Live (the owner's Mac mini, then the Linux box with Xvfb for the X11 path):** on the Mac, drag two fixture files from Keel onto a Finder window and onto TextEdit; copy lands, the originals stay. On Linux under Xvfb with `xdotool` driving the pointer, drag onto a tiny XDND-aware target (write a 60-line Python/Tk or `xclip`-based receiver in the scratch folder, never in the repository) and check the URI list arrives.

**Docs:**
- `docs/files.md` (Drag and drop: all three platforms, the Wayland note), `docs/features.md`, README roadmap (remove the item), `docs/parity.md` (row 15 done).
- CHANGELOG: Added, Known limitations (Wayland; no drag image on X11 if that is what lands).

**Commits:**
- `feat(vfs): drag files out of Keel on macOS`
- `feat(vfs): drag files out of Keel on X11`
- `docs: drag-out on macOS and Linux`

### Task 56: an icon or color per folder (worktree `task56`)

**Goal:** A folder can carry a color and an icon (an emoji or one of the icon theme's folder icons), shown in the sidebar, the file list, the grid and Ctrl+P results. Atlas has it; parity gap #17.

**Read:**
- `crates/keel-core/src/tags.rs` and `schema.sql` (how per-path library data is stored and migrated), `crates/keel-api/src/ops.rs` (`tags.set` as the previewed-operation pattern for library-only changes).
- `crates/keel-app/src/icon_theme.rs` (`folder_icon`), `icons.rs`, `sidebar.rs`, `view_details.rs`, `view_grid.rs`, `jump.rs`.
- `docs/library.md`, `docs/files.md`.

**Design points:**
- **Storage:** a `folder_style` table in `library.db` keyed by the folder's library path (source id + relative path), with `color` (a `#rrggbb` string) and `icon` (an emoji string of one grapheme, or `theme:<name>` for an icon theme folder icon). Folders outside a library source cannot be styled; the menu entry says "Add the folder's drive to the library to style it".
- **UI:** right-click a folder → **Folder color** (the tag palette's colors plus Clear) and **Folder icon** (a small emoji picker of 40 common emoji plus "Type an emoji…", plus the icon theme's named folder icons when a theme is installed, plus Clear). The color tints the folder icon in every view and draws a dot after the name in Details; the emoji replaces the folder icon. The sidebar's library section and Ctrl+P results use the same style.
- **API:** `library.folder_style` (read) and `library.set_folder_style` (previewed), documented; the daemon path works.
- **Library sync:** styles sync between devices like tags do (`crates/keel-core/src/sync.rs`): add them to the synced kinds, or document that they are per device if the sync format cannot take a new kind without a format bump (say which in the commit).

**Tests:**
- Unit tests of the color/icon validation (a non-emoji string, two graphemes, a `theme:` name that does not exist, a color that is not `#rrggbb`).
- Integration: set, read back, clear; a renamed or moved folder keeps its style when the library index records the move (test through the index's move handling); a removed source drops its styles.
- A walkthrough flow: right-click, Folder color, pick one, the dot shows; Folder icon, pick an emoji, the row shows it; Clear both.
- **Live (desktop):** style three fixture folders, restart Keel, the styles are back; the sidebar and Ctrl+P show them.

**Docs:**
- `docs/files.md` (a "Folder colors and icons" section), `docs/library.md`, `docs/api.md`, `docs/features.md`, `docs/parity.md` (row 17 done).
- CHANGELOG: Added, Known limitations (library sources only; sync status).

**Commits:**
- `feat(core): folder colors and icons in the library`
- `feat(app): folder colors and icons in the views`
- `docs: folder styles`

### Task 57: filter chips for library search (worktree `task57`)

**Goal:** The library search tab offers chips for the common filters, so a friend never has to learn `ext:pdf tag:taxes size:>10mb`. Spacedrive v1 has them; parity gap #18.

**Read:**
- `crates/keel-core/src/search.rs` (`LibraryQuery::parse`: every term and its syntax: `ext`, `size`, `kind`/`type`, `tag`, `in`/`source`, dates, favorites) and `search_tests.rs`.
- `crates/keel-app/src/search_tab.rs` (the bar, the backend combo), `library_ui.rs` (`chip`), `tab.rs`.
- `docs/library.md` (the query syntax section), `docs/getting-started.md`.

**Design points:**
- **The query string stays the truth.** A chip row under the search bar, shown when the Library backend is selected: **Kind** (image, video, audio, document, archive, code, other), **Type** (extension: a text field with suggestions from the index's top extensions), **Tag** (the tag chips), **Source**, **Size** (under 1 MB, 1–100 MB, over 100 MB, over 1 GB), **Modified** (today, this week, this month, this year), **Favorites**. Clicking a chip edits the query string with the matching term; editing the string updates the chips (parse → highlight the chips that are active). A chip the parser cannot express is not offered.
- **Discoverable syntax:** hovering a chip shows the term it adds, so the syntax is taught in passing.
- **Keyboard:** the chip row is reachable with Tab from the search box; Space toggles; every chip has an accessibility name.
- **Web client:** the search page of the web client gets the same chips if its search uses the same parser (`crates/keel-web`); otherwise document it as desktop-only.

**Tests:**
- Unit tests: chip → term for every chip; term → active chip for every term the parser accepts; a query with terms the chips cannot show keeps them untouched.
- A walkthrough flow: open the search tab, choose Library, click Kind → Document and Tag → the fixture tag, the query string reads as expected and the results match; type a term by hand and the chip lights.
- **Live (desktop):** on the fixture library, build three searches with chips only.

**Docs:**
- `docs/library.md` (Searching: chips first, syntax second), `docs/getting-started.md`, `docs/features.md`, `docs/parity.md` (row 18 done).
- CHANGELOG: Added.

**Commits:**
- `feat(app): filter chips for library search`
- `docs: filter chips`

### Task 58: tag assign mode, `keel op`, and the agent skill (worktree `task58`)

**Goal:** Two small items. (a) A tag assign mode: press a key, then number keys 1–9 toggle the first nine tags on the selection while a bar shows which number is which (Spacedrive v1; gap #19). (b) `keel op <name> [--params <json>] [--execute]` runs any API operation from the shell with the preview-then-execute protocol, and `docs/agent-skill.md` is a skill file an agent can load to drive Keel (gap #25).

**Read:**
- `crates/keel-app/src/library.rs` (`LibCmd::TagPicker`, `SetTag`), `keys.rs`, `palette.rs`, the toast and status bar code.
- `crates/keel-app/src/cli.rs`, `commands.rs` (how `search`, `tag`, `plan` call the API in-process or through the daemon), `crates/keel-api/src/ops.rs` (the registry: names, schemas, `previewed!` vs `now!`), `docs/api.md`.
- `crates/keel-app/src/commands.rs` `mcp` (the MCP server lists the same operations).

**Design points:**
- **Assign mode:** `Ctrl+Shift+T` (check `keys.rs` for a free chord; also in the palette as "Assign tags with number keys") enters the mode; a bar above the file list shows `1 Receipts  2 Taxes  … 9 …` with each tag's color and a count of selected items that carry it; keys 1–9 toggle; `0` or Esc leaves; the mode follows the selection; moving to another folder leaves the mode. More than nine tags: the bar shows the first nine by name and says "Shift+number for 10–18".
- **`keel op`:** `keel op list` prints every operation with its one-line description and whether it previews; `keel op <name> --params '<json>'` (or `--params-file`) calls it: a `now!` operation prints its result; a `previewed!` operation prints the preview (plan id, changes, warnings) and exits 0, and only `--execute` runs `execute` with the preview's `plan_id` and `input_hash` after printing it; `--json` for machine output (the default when stdout is not a terminal). Through the daemon when one runs, else in-process, like the other commands. Exit codes as the other subcommands.
- **The agent skill:** `docs/agent-skill.md` in the SKILL.md shape (name, description, when to use, the two-step protocol, the `keel op` and `keel mcp` forms, the safety rules: never `--execute` without showing the preview, never permanent deletes without the user's words, how to read errors), plus `skills/keel/SKILL.md` as a copy an agent runtime can install (the README says where). Keep both in sync with a test that diffs them.

**Tests:**
- Assign mode: a walkthrough flow (enter, 1 toggles the first tag on two selected files, the bar's count updates, Esc leaves); a unit test of the bar's labels with 0, 3, 9 and 12 tags.
- `keel op`: CLI tests through the existing CLI test harness: `list`, a `now!` call (`library.stats`), a `previewed!` call without and with `--execute` (`tags.set` on a fixture), a wrong name, invalid JSON, a params object that fails the schema (the error names the field).
- The skill doc and its copy are identical (test).

**Docs:**
- `docs/library.md` (Tags: assign mode), `docs/api.md` (`keel op`), `docs/agent-skill.md` (new), README (a line under the agent section), `docs/features.md`, `docs/parity.md` (rows 19 and 25 done).
- CHANGELOG: Added.

### Task 59: the inspector panel (worktree `task59`)

**Goal:** One panel that shows, for the selected item, what the library knows: copies (other paths with the same content id, across sources and devices), provenance (source, volume, first seen, last hashed, size and content id), history (the op log entries that touched it: moved, renamed, copied, tagged), tags and favorite, and the totals for a folder. Spacedrive's inspector; parity gap #21.

**Read:**
- `crates/keel-app/src/preview_panel.rs` (the panel's layout and how it follows the selection), `dialogs/properties.rs` (`gather`), `crates/keel-core/src/oplog.rs`, `index.rs` (copies by content id), `totals.rs`, `crates/keel-api/src/ops.rs` (`library.stats`, `tags.tagged`, whatever lists duplicates).
- `docs/library.md` ("Copies", "Protection"), `docs/files.md`.

**Design points:**
- **Where:** a second tab of the preview panel, **Inspector** (the panel keeps **Preview**); `Ctrl+I` toggles it; the palette entry "Show inspector". It follows the selection like the preview, with a 150 ms debounce, and reads on a worker.
- **Sections:** Overview (name, kind, size, dates, path with a copy button), Library (source, volume with its state and backup mark, content id with a copy button, first seen, last hashed, protection count), Copies (each other path as a clickable row that navigates; "not hashed yet" when unknown), History (newest first, from the op log: when, what, where to/from; up to 50 with "Show all" opening the library's jobs view filtered), Tags (chips, with the picker button), and for a folder the totals from `totals.rs` (size, files, folders, biggest child).
- **API:** one read operation `library.inspect` returning all of it for one path (bounded lists), so the daemon path and agents get the same data; documented.
- **Outside the library:** the Overview still works from the file system; the other sections say "not in the library".

**Tests:**
- Unit tests of the history row formatting and of the bounded lists.
- Integration: `library.inspect` on a fixture with a hashed copy in a second source, a renamed file (history shows it), a tagged file.
- A walkthrough flow: select a file, Ctrl+I, the Copies row navigates to the copy; select a folder, totals show.
- **Live (desktop):** on the fixture library with two sources holding the same files.

**Docs:**
- `docs/files.md` (Inspector), `docs/library.md`, `docs/api.md` (`library.inspect`), `docs/features.md`, `docs/parity.md` (row 21 done).
- CHANGELOG: Added.

### Task 60: folder operations (worktree `task60`)

**Goal:** The folder operations Spacedrive lists, each as a previewed plan: **Merge folders** (move everything from the selected folders into one, with the usual conflict rules), **Flatten** (move every file from the subfolders up into the folder, then remove the empty subfolders), **Organize** (move files into subfolders by extension group, or by year/month of the modified date), **Set attributes** (hidden, read-only; on Unix the mode bits for owner/group/other), **Create link** (symlink, and on Windows a junction for folders or a hard link for files). Parity gap #26.

**Read:**
- `crates/keel-core/src/plan.rs` (plan kinds, previews, execution, the undo journal hooks), `crates/keel-vfs/src/ops.rs` (moves, `rename_noreplace`, the same-volume fast path), `crates/keel-app/src/undo.rs` (which kinds are undoable), `crates/keel-api/src/ops.rs` (the `plan.*` operations and `execute`), `dialogs/`.
- `docs/library.md` ("Preview before you act"), `docs/files.md` (keyboard table), `docs/api.md`.

**Design points:**
- **All through plans:** each operation is a new plan kind (or a composition of moves where a plain move plan already fits: merge and flatten are moves, so build them as move plans with a generated item list and a title; organize the same; attributes and links are new small kinds). The preview lists every item and its target, names, with the conflict rule chosen in the dialog (Skip / Rename new / Overwrite as for copies); execution goes through the existing job, cancel and progress; the preview is refused at execute time when the disk no longer matches (the `input_hash` rule).
- **Undo:** merge, flatten and organize record their moves (undo moves them back, refusing when a target is taken); attributes record the old values; links are trashed on undo.
- **Links:** a symlink on Windows needs Developer Mode or elevation: say so in the error and offer the junction (folders) or hard link (files) instead; never elevate.
- **Dialogs:** **Merge into…** (pick the destination among the selected folders), **Flatten** (confirm, shows the count), **Organize by…** (extension groups / year / year-month), **Attributes…** (checkboxes, with the current values), **Create link…** (kind and target name). All in the context menu for folders (and files for links/attributes) and the palette.
- **API:** `plan.merge`, `plan.flatten`, `plan.organize`, `plan.set_attributes`, `plan.link`, previewed, documented with examples; the CLI gets `keel plan merge|flatten|organize|attrs|link`.

**Tests:**
- Integration tests in a temporary tree for each operation: the preview lists exactly the right items; execution produces the expected tree; conflicts follow the rule; cancel leaves a consistent tree; undo restores; a changed disk refuses the plan.
- Windows: a junction and a hard link; a symlink that is refused without the privilege (the error says so).
- A walkthrough flow: Organize by extension on a fixture folder, the preview shows the groups, Enter runs it, Ctrl+Z puts it back.
- **Live (desktop):** merge two fixture folders, flatten one, organize by year.

**Docs:**
- `docs/files.md` (a "Folder operations" section), `docs/library.md`, `docs/api.md`, `docs/features.md`, `docs/parity.md` (row 26 done).
- CHANGELOG: Added, Known limitations (what undo cannot restore).
