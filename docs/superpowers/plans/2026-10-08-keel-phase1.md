# Keel Phase 1 (MVP) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A usable Windows file manager: dual pane + tabs + sidebar, Everything search, fuzzy folder jump, previews (code/image/pdf/csv/xlsx/docx/video thumbnail), copy/move/delete/rename with progress, open-with, dark/light theme, crash-safe session restore.

**Architecture:** Cargo workspace. `keel-vfs` owns paths + the `Provider` trait + `LocalProvider`. `keel-search` wraps Everything's IPC DLL and nucleo fuzzy matching. `keel-preview` turns bytes into a `Preview` enum off-thread. `keel-app` is the egui/eframe UI over those three. UI never calls `std::fs` directly.

**Tech Stack:** Rust stable (MSVC), eframe/egui 0.29+, wgpu backend, `windows` crate, nucleo, syntect, image, resvg, pdfium-render, docx-rs, calamine, csv, notify, anyhow, thiserror, serde+toml, tracing. ffmpeg CLI (already installed) for video thumbs.

**Spec:** `docs/superpowers/specs/2026-10-08-keel-design.md`

## Global Constraints

- Targets: Windows 10/11 x64 (daily driver, ships first), macOS arm64/x64, Linux x64. Every OS-specific call lives in a `cfg(target_os)` module behind a shared interface (spec 2.9). Nothing in `keel-app` may use the `windows` crate directly.
- CI matrix windows-latest, macos-latest, ubuntu-latest must stay green for every commit on `main`. Developer builds on JAMES-DESKTOP use `stable-x86_64-pc-windows-msvc`.
- `cargo fmt --check` and `cargo clippy --all-targets -- -D warnings` must pass before every commit.
- No hostnames, IPs, usernames, keys or secrets in the repo (public repo). Profiles live in `%APPDATA%\Keel`.
- License headers not required; `LICENSE-MIT` + `LICENSE-APACHE` at root; third-party binaries listed in `THIRD_PARTY.md`.
- Third-party binaries (`Everything64.dll` on Windows; `pdfium.dll` / `libpdfium.dylib` / `libpdfium.so`) are NOT committed; `scripts/fetch-deps.ps1` (Windows) and `scripts/fetch-deps.sh` (macOS/Linux) download them into `target/deps/` and build copies next to the binary.
- UI thread never blocks on IO: listing, previews, file ops run on worker threads and message back.
- A 50,000-entry folder must list in under 150 ms on JAMES-DESKTOP (measured by `cargo test -p keel-vfs --release -- --ignored perf`).
- Every destructive local op goes to the OS trash (`trash` crate), never permanent delete, in Phase 1.
- Commit after every task. Conventional commit prefixes: `feat:`, `fix:`, `test:`, `chore:`, `docs:`.

## Review Focus

1. Paths longer than 260 chars or with trailing spaces/dots: listing, rename and delete must work (use `\\?\` prefix). Test in Task 2.
2. A folder that disappears while open (USB unplug, network drop): pane keeps last listing, shows toast, no panic. Test in Task 5.
3. Everything.exe not running: search tab shows "Everything is not running" and the rest of the app works. Test in Task 3.
4. A preview that panics or takes >5 s (corrupt PDF, 2 GB CSV): preview panel shows error/"too large", UI stays responsive. Test in Task 4.
5. Copy onto itself / copy into own subfolder / name collision: refused or prompted, never data loss. Test in Task 6.
